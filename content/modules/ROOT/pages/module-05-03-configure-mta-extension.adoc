[IMPORTANT]
====
In this lab, we will use the **Migration Toolkit for Applications** Visual Studio Code extension—the **MTA extension** in a Red Hat Dev Spaces environment that provides a VS Code-based GUI.

**Developer Lightspeed** is not a separate extension. It is MTA's AI-powered code refactoring feature. The **MTA extension** is what is installed in the IDE; it includes both MTA static code analysis and Developer Lightspeed (generative AI).
====

[.goal]
.Goal
[NOTE]
====
Prepare the **OpenShift Dev Spaces** workspace and **MTA extension** for the rest of the lab: open the **parasol-insurance-eap** project, create a **migration profile** (source and target technologies), and connect **Developer Lightspeed** to the LLM via **GenAI** / **provider-settings.yaml** so you can analyze and modernize Parasol Insurance’s legacy EAP application with AI assistance.
====

We will start by setting up the development environment with AI capabilities to start modernizing Parasol Insurance's `parasol-insurance-eap` application.

== Exercise 2: Configure MTA profiles and GenAI provider

image::module-05-mta-dls/dls-03.png[VSCode Tab,link=self,window=blank,title="Manage profiles"]

Managing multiple profiles is a powerful feature of the MTA extension. It allows you to switch between different analysis profiles easily. You can create a new profile by clicking on the "New Profile" button as shown in Step 3 in the image below. We have already created two profiles one with custom rules `audit-logging` and the other `quarkus-profile`. to migration our applicaiton to Quarkus. Click on the `Manage Profiles` button to open the profiles management panel.

image::module-05-mta-dls/dls-04.png[VSCode Tab,link=self,window=blank,title="VSCode Tab"]

Review the profiles and select the `quarkus-profile` profile by clicking on the profile name.

image::module-05-mta-dls/dls-05.png[VSCode Tab,link=self,window=blank,title="Review profiles"]

Click on the "Activate Profile" button to activate the profile. Once done, click on the right panel again to open the provider settings configuration. As shown in the image below.

image::module-05-mta-dls/dls-06.png[VSCode Tab,link=self,window=blank,title="Gen-AI Provider Settings"]

This should open the provider settings configuration. MTA uses the provider settings to connect to the LLM. To configure the LLM, replace the following configuration with your API key `{litellm_virtual_key}` and base URL `{litellm_api_base_url}`.

[.console-input]
[source,yaml,subs="+attributes,macros+"]
----
models:
  OpenShift: &active
    environment:
      OPENAI_API_KEY: "$KEY$"
    provider: ChatOpenAI
    args:
      model: "llama-scout-17b"
      configuration:
        baseURL: "$BASE_URL$"
----

Confirm the Dev Spaces environment and MTA extension (including Developer Lightspeed) are set up correctly.

* The File _EXPLORER_ lists the **parasol-insurance-eap** directory
* Expand directories with the file explorer arrows if needed — you should see packages such as `com.parasol.mdb` (`EmailIntakeMDB`) and `com.parasol.ejb` (`ClaimService`)
