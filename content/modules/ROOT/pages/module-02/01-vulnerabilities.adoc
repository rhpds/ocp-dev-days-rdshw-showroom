= Dealing with Vulnerabilities Early
include::partial$_attributes.adoc[]
:imagesdir: ../../assets/images

The traditional approach to security is to scan at the end of the pipeline -- or worse, after deployment. By then, fixing vulnerabilities means rework, delays, and emergency patches. A better approach is to **shift left**: give developers the tools to identify and fix vulnerabilities as early as possible, while they are still writing code.

In this section, you will set up your secured development environment, then use Red Hat Dependency Analytics to find and fix vulnerabilities in the application's dependencies -- before you even push a commit.

NOTE: This module does not cover the full capabilities of Red Hat Developer Hub or how it supports developers in their daily workflow. For the developer experience, see xref:module-01/00-intro.adoc[Module 1: The Developer Experience]. Here, we focus on the security guardrails added to the development process.

=== Why is this important?

Giving developers vulnerability information at the earliest possible stage -- while they are still writing code -- lets them make informed decisions. They can:

* Choose to update a framework version before a pipeline ever runs
* Understand the difference between a Lightwell backport (a drop-in fix that does not change the dependency version) and an upstream remediation (a version bump that may introduce breaking changes)
* Prioritize which vulnerabilities to fix based on severity and exploitability

This is the essence of **shift-left security**: the developer has the information and the tools to act, rather than discovering problems in a CI/CD failure hours later.

=== How was it done?

To keep the exercise readable, we have added the details below. Expand to read how it was done.

.**Open to view implementation details**
[%collapsible]
====
Red Hat Dependency Analytics queries a backend service called the **{tpa_url}[Trusted Profile Analyzer (TPA)^]**. In this environment, TPA is deployed on the cluster and ingests vulnerability data from multiple sources:

* **CVE List v5** -- the industry-standard vulnerability database
* **GitHub Security Advisories (GHSA)** -- vulnerability reports from the open source community
* **Lightwell** -- Red Hat's commercial vulnerability intelligence service, providing backport remediations and drop-in replacements that are not available in public databases

RHDA is a VS Code (and IntelliJ) extension that has been configured via the workspace settings to use this cluster's TPA instance:

[source,json]
----
"redHatDependencyAnalytics.backendUrl": "https://rhda.{subdomain}"
----

When you open a `pom.xml` (or `package.json`, `go.mod`, etc.), RHDA sends the dependency tree to the backend, which matches it against the ingested vulnerability data and returns enriched results including Lightwell remediations.

You can also open Trusted Profile Analyzer directly from the Dependency Analytics report:

image::m02-rhda-tpa-link.png[Take me there button to open TPA from RHDA report,link=self,window=blank,width=700]
====
