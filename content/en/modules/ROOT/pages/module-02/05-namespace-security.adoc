The secured pipeline ensures that only properly signed, scanned, and approved images are *built*. But what stops someone from bypassing the pipeline entirely and deploying an unsigned image directly with `oc` or `kubectl`? That is where the **Sigstore Policy Controller** comes in.

The Policy Controller is a Kubernetes admission controller that intercepts pod creation requests and verifies container image signatures and attestations *before* the pod is allowed to run. In Parasol's secured production namespace, three policies must be satisfied:

* The image must be **signed** (by Tekton Chains or Red Hat)
* The image must carry **proof of a signed commit** in its SLSA attestation
* The image must have a **signed release approval** attestation

=== Why is this important?

Pipelines are a critical security control, but they can be bypassed -- someone with namespace access could use `oc apply` to deploy any image. The Policy Controller closes this gap:

* It operates at the **Kubernetes admission layer**, below the pipeline
* It verifies signatures and attestations at **deployment time**, not build time
* It applies to **all pod creation**, regardless of how the deployment was initiated (ArgoCD, `oc`, Helm, manual YAML, etc.)
* It creates **defense in depth** -- even if the pipeline is compromised, unsigned images with missing required attestations (and values therein) cannot run

=== How was it done?

To keep the exercise readable, we have added the details below. Expand to read how it was done.

.**Open to view implementation details**
[%collapsible]
====
The **Sigstore Policy Controller** is installed via the RHTAS operator and configured through `ClusterImagePolicy` Custom Resources.

Three policies are applied to every image deployed in the `{user}-secured-prod` namespace:

[cols="1,2",options="header"]
|===
| Policy | What it checks

| `parasol-image-signature-required`
| Image must be signed by either Tekton Chains (keyless, via Fulcio/Rekor) or Red Hat (release3 public key)

| `parasol-signed-commit-required`
| SLSA provenance attestation must contain a `verify-commit-signature` task with `SIGNATURE_STATUS: SIGNED`

| `parasol-release-approval-required`
| A custom attestation (`parasol-insurance.com/releases/v1`) must exist with `release.approved: true`, signed by a `*@demo.redhat.com` identity
|===

Each policy has **two authorities** (OR logic):

* **Tekton Chains / User identity** -- verifies signatures from the cluster's Sigstore infrastructure (Fulcio + Rekor)
* **Red Hat signed** -- verifies signatures using the Red Hat release3 public key, allowing Red Hat base images (like the PostgreSQL database) to pass without Chains signatures

The namespace is opted into enforcement by the label:

[source,yaml]
----
metadata:
  labels:
    policy.rhtas.com/include: "true"
----

Only namespaces with this label are subject to the policies. Build namespaces, sandbox namespaces, and non-production environments are not labeled and are not affected.
====
