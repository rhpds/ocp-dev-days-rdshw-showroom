= Signing Your Commits
include::partial$_attributes.adoc[]
:imagesdir: ../../assets/images

Every commit tells a story -- but how do you know the story is true? Commit authors can be faked with a single `git config` command. Repository access can be compromised. SSH or GPG keys can be lost, stolen, or shared. Traditional code signing relies on long-lived key pairs that developers must manage, rotate, and protect -- and many developers simply do not.

**Sigstore keyless signing** here, with **Red Hat Trusted Artifact Signer (RHTAS)**, deployed as a cluster infrastructure component, solves this by tying the signature to the developer's *identity* rather than a key pair. When you sign a commit, you authenticate with your organization's identity provider (in our case, Keycloak SSO). A short-lived certificate is issued by Fulcio (RHTAS' Certificate Authority), the signature is recorded in Rekor's transparency log, and the certificate expires within minutes. There are no keys to manage, lose, or rotate.

In this section, you will commit the vulnerability fix you just made and sign it with your identity.

=== Why is this important?

* **Accountability**: Every commit is cryptographically tied to a verified identity -- not just a name in a git config
* **Tamper evidence**: If anyone modifies a signed commit, the signature breaks
* **No key management**: Developers do not need to generate, store, or rotate signing keys
* **Transparency**: Every signature is recorded in a public transparency log (Rekor), creating an auditable trail
* **Pipeline enforcement**: Later stages of the pipeline will verify that commits were signed before building

=== How was it done?

To keep the exercise readable, we have added the details below. Expand to read how it was done.

.**Open to view implementation details**
[%collapsible]
====
Git has been configured to use **gitsign** as the signing program. This is set up automatically when the Dev Spaces workspace starts, via the devfile's `postStart` command:

[source,bash]
----
git config --global gpg.format x509
git config --global gpg.x509.program gitsign
git config --global commit.gpgsign true
git config --global gitsign.fulcio "https://fulcio-server-trusted-artifact-signer.{subdomain}"
git config --global gitsign.rekor "https://rekor-server-trusted-artifact-signer.{subdomain}"
git config --global gitsign.issuer "https://sso.{subdomain}/realms/sso"
----

The **Sigstore keyless flow** works as follows:

. The developer initiates a commit
. Gitsign redirects to the OIDC provider (Keycloak) for authentication
. After authentication, gitsign requests a short-lived certificate from **Fulcio** (the certificate authority)
. Fulcio issues a certificate embedding the developer's email as the Subject Alternative Name
. Gitsign signs the commit with this certificate
. The signature is recorded in **Rekor** (the transparency log) for auditability
. The certificate expires within minutes -- but the Rekor entry proves the signature was valid at the time of signing

Since Dev Spaces runs in a container without a local browser, the **gitsign-credential-cache** daemon handles the OIDC flow by presenting a verification code that the developer pastes into a terminal. On a local IDE, gitsign would open the browser directly.
====
