In this lab, we will use the **Migration Toolkit for Applications** Visual Studio Code extension—the **MTA extension** in a Red Hat Dev Spaces environment that provides a VS Code-based GUI.

**Developer Lightspeed** is not a separate extension. It is MTA's AI-powered code refactoring feature. The **MTA extension** is what is installed in the IDE; it includes both MTA static code analysis and Developer Lightspeed (generative AI).

== Exercise 2: Configure MTA profiles and GenAI provider

Excellent! You have made it to Exercise 2, this also means we now have a working environment to configure our Analysis profiles.

Managing multiple profiles is a powerful feature of the MTA extension. It allows you to switch between different analysis profiles easily. You can create a new profile by clicking on the "New Profile" button as shown in Step 3 in the image below.

We shall start with creating our first profile, the `quarkus-profile` — to migrate our application to Quarkus. In xref:module-05/module-05-05-custom-rules-audit-logging.adoc[Section 5: Custom rules (audit logging)] we will explore the audit-logging custom rules.

Click on the `Manage Profiles` button to open the profiles management panel.

image::module-05-mta-dls/05-03-dls-06.png[VSCode Tab,link=self,window=blank,title="VSCode Tab"]

- Create a new profile `quarkus-profile`
- Profile Name: `quarkus-profile``
- Target Technologies: `quarkus``, `quarkus3+``, `jakarta-ee``

image::module-05-mta-dls/05-03-dls-07.png[VSCode Tab,link=self,window=blank,title="Review profiles"]

Since this is the first profile it will automatically be made active by the DLS extension. 

Review that you have the correct details as listed above and close this tab.


The screenshot above shows that control next to **Open Analysis** click it and follow the instructions below. 
Open the GenAI provider settings from the MTA panel as shown in the next image.

- *1* Click the settings `⚙︎` icon.
- *2* Click `Configure GenAI Settings`

image::module-05-mta-dls/05-03-dls-08.png[VSCode Tab,link=self,window=blank,title="Gen-AI Provider Settings"]

This should open the provider settings configuration. MTA uses **provider-settings.yaml** to connect to the LLM.

The lab workspace is pre-configured with provider settings and LiteLLM credentials. Confirm the **OpenShift** model is active and the base URL / API key fields are populated (they should already match your lab environment).

TIP: Provider settings are normally pre-filled for this lab. Use the YAML below only if the file is empty or incomplete (for example after a workspace reset) — this is a recovery step, not an expected bug.

[.console-input]
[source,yaml,subs="+attributes,macros+"]
----
models:
  OpenShift: &active
    environment:
      OPENAI_API_KEY: "{litellm_virtual_key}"
    provider: ChatOpenAI
    args:
      model: "qwen3-235b"
      configuration:
        baseURL: "{litellm_api_base_url}"
active: *active
----

Confirm that the settings have the following values in the following fields.

- `OPENAI_API_KEY` : this is the LLM key to the model hosted on OpenShift AI
- `model` : the name of the model we are using
- `baseURL` : the url/route at which the model is listening to requests via the chat completions API.
- `active` : Finally we want to ensure that this profile is active. MTA can be configured with multiple LLMs however only one LLM can be active at a time.

Save the `provider-settings.yaml` file if you edited it (`Ctrl+S` / `Cmd+S`), then return to the **MTA Analysis View** tab.

With GenAI configured and `quarkus-profile` selected, start the analysis server and run your first analysis. The image below shows both steps:

- *1* Click **Start** (power icon) in the top-right of the MTA Analysis View. Wait until **Server Status** changes from a red **Stopped** badge to a green **Running** badge. While the server is stopped, **Run Analysis** stays disabled.
- *2* When the server is **Running**, click **Run Analysis** next to the `quarkus-profile` dropdown.

image::module-05-mta-dls/05-03-dls-09.png[Start MTA server and run analysis,link=self,window=blank,title="Start MTA server and run analysis"]

NOTE: The first analysis can take a minute or two. When it finishes, the MTA Analysis View lists migration issues for `parasol-insurance-eap`. You will review those findings in the next section.

* Finally, ensure that the analysis ran and you can see multiple entries (we will review them in detail in the next section).

* Click on the file icon on the left side of the Dev Spaces environment
* The File _EXPLORER_ lists the **parasol-insurance-eap** directory (your GitLab copy, not a shared sample)
* Expand directories with the file explorer arrows if needed — you should see packages such as `com.parasol.mdb` (`EmailIntakeMDB`) and `com.parasol.ejb` (`ClaimService`)
