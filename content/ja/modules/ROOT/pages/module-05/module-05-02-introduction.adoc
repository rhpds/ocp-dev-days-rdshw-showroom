Migration Toolkit for Applications は、クラウド移行に向けてアプリケーションを評価・分析する業界をリードするソリューションとして、長年にわたり利用されています。 **Developer Lightspeed** (**DLS**) は、MTA の **AI を活用したコードのリファクタリング** 機能であり、独立した extension ではありません。生成 AI を活用した移行機能を開発者の IDE に導入し、アプリケーションのモダナイゼーションに対する組織の取り組み方を変革します。



== アプリケーションのモダナイゼーションにおける課題

企業がアプリケーションポートフォリオをモダナイズする際には、次のような重大な課題に直面します。

* **セキュリティ上の懸念** - 古いアプリケーションやフレームワークは、ビジネス運用に重大なリスクをもたらし、データ侵害やコンプライアンス違反につながる可能性があります。
* **レガシーシステムの複雑さ** - レガシーコードベースは最新のプラットフォームとの互換性がないことが多く、依存関係が密結合しているうえ、現在の開発チームにとって馴染みがない場合があります。
* **優先事項の競合** - 組織は、限られたリソースの中でモダナイゼーションの緊急性とのバランスを取る必要があり、既存アプリケーションの改善よりも新機能を優先することがよくあります。
* **規模と一貫性** - 大企業では、同様の変更が必要なアプリケーションが何百もある場合があり、手作業での移行は現実的ではありません。

Developer Lightspeed では、static analysis と生成 AI を使用し、シンプルな 6 ステップの手法でアプリケーションを簡単に移行できます。

== Developer Lightspeed によるモダナイゼーションの変革

**Red Hat Developer Lightspeed for MTA** は、static analysis と **Developer Lightspeed** (生成 AI) の両方を活用する MTA のモダナイゼーションを指します。IDE では、Visual Studio Code 向け **MTA extension** により、MTA static analysis と Developer Lightspeed をまとめて利用できます。この組み合わせにより、次の課題に対応します。

* **GenAI でアプリケーションのモダナイゼーションを加速** - MTA extension は、MTA で実績のある static code analysis と Developer Lightspeed の生成 AI を組み合わせ、移行上の問題を特定して、コンテキストに応じた解決策を提案します。AI は IDE 内で個々の状況に合わせたコードの推奨事項を生成するため、コンテキストの切り替えが不要になり、開発者は作業に集中できます。コード変更による波及的な影響も自動的に処理し、リファクタリングの全過程でコードの整合性を保ちます。さらに、移行メトリクスを追跡し、過去の解決策から学習することで、時間とともに推奨内容を継続的に改善します。

* **開発者が信頼できる有用なリファクタリング済みコードの提案** - このシステムはルールベースの分析を使って、どの移行上の問題を探し、どのように解決するかを LLM に示すことで、実績のある移行パターンに基づいた推奨を行います。各提案には、何を変更する必要があるのか、またその理由について明確な説明が含まれているため、開発者は修正案の根拠を理解できます。IDE のリアルタイム診断データにより、仮定上の問題ではなく、実際のコンパイルや実行時の問題に対処する修正が提案されます。全工程を通じて開発者が変更を確認して承認するため、リファクタリングを完全に制御し、コード品質を確保できます。

* **カスタムおよびプロプライエタリなテクノロジーをモダナイズ** - Developer Lightspeed では、組織固有のフレームワークに対応する条件やアクションを指定するカスタムルールを作成できるため、AI が独自のテクノロジースタックを理解して活用できます。この機能により、標準の移行ルールではカバーされないプロプライエタリなライブラリーや社内ライブラリーを使用するアプリケーションのコード変換を自動化できます。組織の知識をすぐに使える移行パスに追加し、特定のビジネスニーズに合わせてツールを適応させられます。

* **ポートフォリオ全体でモダナイゼーションを拡大** - Developer Lightspeed は移行中に行われた変更から学習し、時間とともに向上する組織の知識を蓄積します。アプリケーション間で類似のパターンを検出すると、ポートフォリオ内の他の同様のアプリケーション向けに、正確な解決策を予測して生成します。この学習機能により、一貫した品質を保ちながら複数のアプリケーションを予測可能かつ効率的にリファクタリングでき、ポートフォリオ規模のモダナイゼーションを実現できます。

* **開発 workflow とのシームレスな統合** - すべての分析とリファクタリングは Red Hat Dev Spaces 内で直接行われるため、開発者は使い慣れた環境を維持できます。詳細な問題、提案された解決策、コード diff を、コンテキストを切り替えたり別のツールを行き来したりせずに確認できます。リファクタリングが完了したら、既存の CI/CD pipeline を通じてリファクタリング済みコードを push し、自動テストと deploy を実行することで、モダナイズしたアプリケーションを既存の開発プロセスにシームレスに統合できます。

* **AI model の選択** - Developer Lightspeed は、ファインチューニングなしで、パブリックまたはセルフホスト型のカスタム LLM を利用できるため、ベンダーロックインを回避できます。RAG アーキテクチャは過去の解決策から学習してナレッジベースに保存し、組織の移行履歴に基づいて推奨内容を継続的に改善します。このシステムは OpenAI 互換 API を通じて複数の LLM provider に対応しており、Red Hat OpenShift AI (エンタープライズ向け model builder と inference server)、Red Hat Enterprise Linux AI (エンタープライズ向け inference server)、vLLM (広く利用されているエンタープライズ向け inference server) を利用できます。この柔軟性により、具体的な要件に応じてパフォーマンス、コスト、データプライバシーのバランスを取れます。
