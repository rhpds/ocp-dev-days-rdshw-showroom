== Lab 5 - LLM Governance

Connectivity Link を使用して、LLM エンドポイントの前にガバナンス層を配置します。複数のサービスティアにわたって、API キー認証とトークンベースのレート制限を適用します。

{empty} +

=== The Scenario

前のラボでは、自然言語で顧客のサポート問題を解決する AI エージェントを構築しました。このエージェントは、チャットインターフェース内からデータベースを照会し、レコードを更新し、ポリシードキュメントを再生成します。

ここで、新しい機能である **顧客プロファイル分析** を追加したいと考えています。サポート担当者が顧客について質問すると、AI はそのデータを分析し、構造化された要約を返します。利用できる分析ティアは 2 つです。

* **Gold** -- 完全なポリシー履歴、請求履歴、ロイヤルティステータス。
* **Silver** -- 直近のポリシーと基本的なプロファイル情報。

Gold は分析がより深く、応答もより豊富なため、より多くのトークンを消費します。Silver はより軽量です。このシステムはフォールバック戦略を備えています。Gold ティアのトークン予算が尽きた場合、サービスは Silver にフォールバックします。Silver も尽きた場合、リクエストは保留されます。

しかし、これらが機能する前に、ガバナンスが必要です。LLM エンドポイントにアクセスできるのは誰か。各ティアはどれだけのトークンを消費できるのか。制御がなければ、無制限の消費によって組織の API 予算が使い果たされるのを防ぐことはできません。

このラボでは、link:https://www.redhat.com/en/technologies/cloud-computing/connectivity-link[*_Red Hat Connectivity Link_*,window=_blank] を使用して、LLM エンドポイントの前に **ガバナンス層** を配置します。2 つのポリシーを実装します。

* **AuthPolicy** -- API キー認証とグループベースの認可を使用して、エンドポイントに _誰が_ アクセスできるかを制御します。
* **TokenRateLimitPolicy** -- 実際のトークン使用量に基づいてレート制限を適用し、各ティアが _どれだけ_ 消費できるかを制御します。

{empty} +

=== Why Connectivity Link?

これはまさに _Red Hat Connectivity Link_ が想定している種類の問題です。link:https://kuadrant.io/[_Kuadrant_ プロジェクト,window=_blank] を基盤とし、*Kubernetes* に AI を考慮したガバナンスをもたらします。

* **トークン認識型レート制限** -- 制限はリクエスト数ではなく、実際に消費されたトークンに基づきます。これにより、階層化された AI サービスが実現可能になります。各ティアは独自のトークン予算を持ち、ゲートウェイで強制されます。
* **コード変更不要** -- ポリシーはインフラストラクチャ層で適用されます。AI エージェントと統合コードはそのままです。
* **Kubernetes ネイティブ** -- ポリシーは標準の CRD であり、`oc apply` で適用し、Git に保存し、PR でレビューします。別個の管理コンソールやベンダーのコントロールプレーンは不要です。
* **合成可能** -- 1 つのポリシーが ID を抽出し、別のポリシーがそれを使ってティアごとのトークン予算を適用します。これらは宣言的に重ねて適用できます。

これらの機能は、Connectivity Link が _Kubernetes Gateway API_ 標準の上に構築されていることから生まれます。ポリシーの設定を始める前に、Gateway API モデルを見てみましょう。

{empty} +

=== The Gateway API Model

Connectivity Link は、*Kubernetes* でトラフィックルーティングを管理する標準である _Kubernetes Gateway API_ の上に重なります。このモデルを理解すると、これからの演習が直感的になります。

構成要素は次のとおりです。

* **GatewayClass + Gateway** -- プラットフォームチームが管理します。トラフィックが _どのように_ クラスターに入るかを定義します。すでにプロビジョニング済みです。
* **HTTPRoute** -- プラットフォームチームまたは開発チームが管理します。トラフィックを _どこへ_ 送るかを定義します（この場合は LLM API）。
