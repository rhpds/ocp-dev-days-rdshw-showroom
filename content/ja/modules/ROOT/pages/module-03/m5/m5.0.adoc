== Lab 5 - LLM ガバナンス

Connectivity Link を使って LLM エンドポイントの前にガバナンス層を配置し、複数のサービスティアにわたって API キー認証とトークンベースのレート制限を適用します。

{empty} +

=== シナリオ

前のラボでは、自然言語で顧客サポートの問題を解決する AI エージェントを構築しました。このエージェントは、チャットインターフェースからデータベースを照会してレコードを更新し、ポリシードキュメントを再生成します。

ここで、新しい機能として **顧客プロファイル分析** を追加します。サポート担当者が顧客について尋ねると、AI が顧客データを分析し、構造化された要約を返します。分析には次の 2 つのティアがあります。

* **Gold** -- ポリシー履歴、請求履歴、ロイヤルティステータスをすべて含む分析。
* **Silver** -- 最近のポリシーと基本的なプロファイル情報に絞った分析。

Gold は分析がより詳細で応答内容も充実するため、より多くのトークンを消費します。Silver はより軽量です。このシステムにはフォールバック戦略があり、Gold ティアのトークン予算が尽きるとサービスは Silver に切り替わります。Silver の予算も尽きた場合、リクエストは保留されます。

ただし、これらを実現するには、まずガバナンスが必要です。LLM エンドポイントにアクセスできるのは誰でしょうか。各ティアが消費できるトークン数はいくつでしょうか。制御がなければ、消費量を抑えられず、組織の API 予算を使い果たしかねません。

このラボでは、link:https://www.redhat.com/en/technologies/cloud-computing/connectivity-link[*_Red Hat Connectivity Link_*,window=_blank] を使って LLM エンドポイントの前に **ガバナンス層** を配置し、次の 2 つのポリシーを実装します。

* **AuthPolicy** -- API キー認証とグループベースの認可を使って、エンドポイントに _誰が_ アクセスできるかを制御します。
* **TokenRateLimitPolicy** -- 実際のトークン使用量に基づくレート制限で、各ティアが _どれだけ_ 消費できるかを制御します。

{empty} +

=== Connectivity Link を選ぶ理由

これはまさに _Red Hat Connectivity Link_ が解決するために設計された課題です。link:https://kuadrant.io/[_Kuadrant_ プロジェクト,window=_blank] を基盤とし、*Kubernetes* に AI を考慮したガバナンスをもたらします。

* **トークン対応のレート制限** -- リクエスト数ではなく、実際に消費されたトークンに基づいて制限します。これにより、各ティアに独自のトークン予算を割り当て、ゲートウェイで適用できるため、階層型 AI サービスを実現できます。
* **コード変更不要** -- ポリシーはインフラストラクチャ層で適用されるため、AI エージェントや統合コードを変更する必要はありません。
* **Kubernetes ネイティブ** -- ポリシーは標準の CRD です。 `oc apply` で適用し、Git に保存して、PR でレビューできます。別の管理コンソールやベンダーのコントロールプレーンは必要ありません。
* **組み合わせ可能** -- あるポリシーで ID を抽出し、別のポリシーでその ID を使ってティアごとのトークン予算を適用します。ポリシーを宣言的に組み合わせて適用できます。

これらの機能は、Connectivity Link が _Kubernetes Gateway API_ 標準を基盤としていることによって実現されています。ポリシーの設定に進む前に、Gateway API モデルを見てみましょう。

{empty} +

=== Gateway API モデル

Connectivity Link は、*Kubernetes* でトラフィックルーティングを管理する標準である _Kubernetes Gateway API_ を基盤としています。このモデルを理解しておくと、以降の演習が分かりやすくなります。

構成要素は次のとおりです。

* **GatewayClass + Gateway** -- プラットフォームチームが管理し、トラフィックが _どのように_ クラスターに入るかを定義します。すでにプロビジョニングされています。
* **HTTPRoute** -- プラットフォームチームまたは開発チームが管理し、トラフィックを _どこへ_ 送るかを定義します（ここでは LLM API です）。
