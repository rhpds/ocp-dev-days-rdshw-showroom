=== Connectivity Link による認証ポリシー
概念と想定されるアーキテクチャを理解できたところで、LLM エンドポイントを保護します。この演習では、HTTPRoute（ `ai-proxy-route` ）に適用される **AuthPolicy** を作成して、キー ベースの認証方式を強制します。これにより、有効な API key を持つ認証済みユーザーだけが LLM にアクセスできるようになります。また、次のステップでレート制限に使用する ID 情報も抽出します。

NOTE: このワークショップでは、わかりやすくするためにシンプルな API key 認証を使用しますが、_Connectivity Link_ は JWT、OAuth2 など、幅広い認証方式をサポートしています。

{empty} +

=== ユーザー Secret を理解する

2 つの API key secret はすでに *事前に作成* されています。どちらのポリシーもこれらの secret のラベルとアノテーションを参照するため、その構造を理解しておくことが重要です。

**Silver tier user:**
[source,yaml,subs="attributes"]
----
apiVersion: v1
kind: Secret
metadata:
  name: trlp-tutorial-api-key-silver-{user-username}
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: my-llm-{user-username}
  annotations:
    kuadrant.io/groups: silver
    secret.kuadrant.io/user-id: {user-username}
stringData:
  api_key: [some_random_string]
type: Opaque
----

この secret の主なフィールド:

* `authorino.kuadrant.io/managed-by: authorino` -- この secret が _Authorino_ （ _Connectivity Link_ の背後にある認証エンジン）によって管理されていることを示します。
* `app: my-llm-{username}` -- ラベルセレクターです。AuthPolicy はこれを使って有効な API key を検出します。
* `kuadrant.io/groups: silver` -- グループへの所属（Silver tier）を示し、適用されるレート制限 tier を決定します。
* `secret.kuadrant.io/user-id: {user-username}` -- 一意のユーザー ID で、ユーザーごとのレート制限のカウンターキーとして使用されます。

{empty} +

**Gold tier** の secret も同じ構造ですが、次の値を持ちます。

* `kuadrant.io/groups: gold`

{empty} +

// == 認証で LLM を保護する

// アーキテクチャとセットアップを理解したので、LLM エンドポイントを保護し、組織内の認証済みユーザーだけがアクセスできるようにします。`ai-proxy-route` HTTPRoute に適用される **AuthPolicy** を作成し、次の項目を強制します:

// 1. **API Key Authentication** -- 有効な Bearer token（既知の secret と一致するもの）を含むリクエストだけを許可します。
// 2. **Group-based Authorization** -- `lite` または `pro` グループに属するユーザーだけが API にアクセスできます。
// 3. **Identity Extraction** -- secret のアノテーションからユーザーのグループとユーザー ID を抽出し、次のセクションで作成する TokenRateLimitPolicy で利用できるよう、下流に渡します。

=== AuthPolicy を確認して適用する

AuthPolicy を確認し、次のコマンドを terminal に貼り付けて *適用* します。

[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: ai-proxy-auth
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  rules:
    authentication:
      api-key-users:
        apiKey:
          selector:
            matchLabels:
              app: my-llm-{user-username}
        credentials:
          authorizationHeader:
            prefix: Bearer
    response:
      success:
        filters:
          identity:
            json:
              properties:
                groups:
                  selector: auth.identity.metadata.annotations.kuadrant\.io/groups
                userid:
                  selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/user-id
        headers:
          authorization:
            plain:
              selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/upstream-token
      unauthenticated:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Unauthenticated",
              "message": "Invalid or missing API Key."
            }
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied. Your account does not have the required permissions (gold/silver)."
            }
    authorization:
      allow-groups:
        opa:
          rego: |
            groups := split(object.get(input.auth.identity.metadata.annotations, "kuadrant.io/groups", ""), ",")
            allow { groups[pass:[_]] == "gold" }
            allow { groups[pass:[_]] == "silver" }
EOF
****

このポリシーの主なフィールド:

* `namespace: {user-username}-devspaces` -- ポリシーはユーザーの namespace に作成されます。
* `name: ai-proxy-route` -- `ai-proxy-route` HTTPRoute を対象とします。この route に一致するすべてのリクエストは認証を通過する必要があります。
* `app: my-llm-{user-username}` -- 有効な API key を見つけるため、このラベルを持つ _Kubernetes_ Secret を検索します。
* `prefix: Bearer` -- `Authorization` header に API key が指定されることを想定します。
* `kuadrant\.io/groups` -- 一致した secret からグループのアノテーションを抽出し、レスポンスフィルターで `groups` として公開します。
* `secret\.kuadrant\.io/user-id` -- ユーザー ID のアノテーションを抽出し、`userid` として公開します。
* `rego` -- グループが `gold` または `silver` のユーザーだけを許可する OPA（Open Policy Agent）ルールです。
