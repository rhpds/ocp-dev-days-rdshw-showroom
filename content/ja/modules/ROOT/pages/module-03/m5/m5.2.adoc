=== Connectivity Link による Auth Policy
ここまでで概念と想定アーキテクチャを理解したので、次は LLM endpoint を保護します。この演習では、HTTPRoute（`ai-proxy-route`）に適用される **AuthPolicy** を作成し、key-based authentication scheme を強制します。これにより、有効な API key を持つ認可済みユーザーだけが LLM にアクセスできるようになります。また、次のステップで rate limiting に使用する identity information も抽出します。

NOTE: この workshop では、わかりやすさを優先してシンプルな API key authentication を使用しますが、_Connectivity Link_ は JWT、OAuth2 など、幅広い authentication method をサポートしています。

{empty} +

=== User Secret を理解する

2 つの API key secret は、すでに *事前作成済み* です。両方の policy がこれらの secret 上の label と annotation を参照するため、その構造を理解することが重要です。

**Silver tier user:**
[source,yaml,subs="attributes"]
----
apiVersion: v1
kind: Secret
metadata:
  name: trlp-tutorial-api-key-silver-{user-username}
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: my-llm-{user-username}
  annotations:
    kuadrant.io/groups: silver
    secret.kuadrant.io/user-id: {user-username}
stringData:
  api_key: [some_random_string]
type: Opaque
----

この secret の主要フィールド:

* `authorino.kuadrant.io/managed-by: authorino` -- この secret が _Authorino_（_Connectivity Link_ の背後にある auth engine）によって管理されていることを示します。
* `app: my-llm-{username}` -- label selector -- AuthPolicy はこれを使用して有効な API key を検出します。
* `kuadrant.io/groups: silver` -- group membership（Silver tier）-- どの rate limit tier が適用されるかを決定します。
* `secret.kuadrant.io/user-id: {user-username}` -- 一意の user ID -- per-user rate limiting の counter key として使用されます。

{empty} +

**Gold tier** の secret も同じ構造ですが、次の値になります。

* `kuadrant.io/groups: gold`

{empty} +

// == Authentication で LLM を保護する

// アーキテクチャとセットアップを理解したので、今度は LLM endpoint を保護し、組織内の認可済みユーザーだけがアクセスできるようにします。`ai-proxy-route` HTTPRoute に適用される **AuthPolicy** を作成し、次の内容を強制します:

// 1. **API Key Authentication** -- 有効な Bearer token（既知の secret と一致するもの）を含むリクエストだけを許可します。
// 2. **Group-based Authorization** -- `lite` または `pro` group に属するユーザーだけが API にアクセスできます。
// 3. **Identity Extraction** -- ユーザーの group と user ID を secret の annotation から抽出し、次のセクションで作成する TokenRateLimitPolicy で使えるように downstream に渡します。

=== AuthPolicy を確認して適用する

AuthPolicy を確認し、次のコマンドを terminal に貼り付けて *適用* してください。

[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: ai-proxy-auth
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  rules:
    authentication:
      api-key-users:
        apiKey:
          selector:
            matchLabels:
              app: my-llm-{user-username}
        credentials:
          authorizationHeader:
            prefix: Bearer
    response:
      success:
        filters:
          identity:
            json:
              properties:
                groups:
                  selector: auth.identity.metadata.annotations.kuadrant\.io/groups
                userid:
                  selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/user-id
        headers:
          authorization:
            plain:
              selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/upstream-token
      unauthenticated:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Unauthenticated",
              "message": "Invalid or missing API Key."
            }
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied. Your account does not have the required permissions (gold/silver)."
            }
    authorization:
      allow-groups:
        opa:
          rego: |
            groups := split(object.get(input.auth.identity.metadata.annotations, "kuadrant.io/groups", ""), ",")
            allow { groups[pass:[_]] == "gold" }
            allow { groups[pass:[_]] == "silver" }
EOF
****

この policy の主要フィールド:

* `namespace: {user-username}-devspaces` -- policy はあなたの namespace に作成されます。
* `name: ai-proxy-route` -- `ai-proxy-route` HTTPRoute を target にします -- この route に一致するすべての request は認証を通過する必要があります。
* `app: my-llm-{user-username}` -- 有効な API key を見つけるために、この label を持つ _Kubernetes_ Secret を探します。
* `prefix: Bearer` -- `Authorization` header に API key があることを前提とします。
* `kuadrant\.io/groups` -- 一致した secret から group annotation を抽出し、response filter で `groups` として公開します。
* `secret\.kuadrant\.io/user-id` -- user ID annotation を抽出し、`userid` として公開します。
* `rego` -- group が `gold` または `silver` のユーザーのみを許可する OPA（Open Policy Agent）rule です。
