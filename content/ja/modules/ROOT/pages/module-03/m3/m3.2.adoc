== Kafka から Rocket.Chat へ

_Matrix_ と _Rocket.Chat_ を双方向でつなぐには、4 つのフローが必要です（イントロで説明したとおりです）。サポート担当者まで顧客メッセージを届ける経路だけでも 2 つ必要です。

* *フロー 1* — Matrix から Kafka へ _(事前構成済み)_
* *フロー 2* — Kafka から Rocket.Chat へ ✏️ _(これを作成します)_

NOTE: 4 つのフローはすべて同じパターンに従います。1 つ作れば、他もほぼ同じです。ラボを短く保つため、手作業で作成するのはフロー 2 のみです。残りの 3 つは最後に利用可能になり、有効化されます。

----

[NOTE]
--
*ループバックイベントとは何ですか？*

すべてのシステムが 1 つの _Kafka_ トピックに公開し、そこから購読します。つまり、_Rocket.Chat_ から送信されたメッセージも、このフローが消費しているのと同じトピックに入るため、そのまま戻ってきてしまう可能性があります。

[.mermaid]
----
flowchart LR
    RC -->|"メッセージ"| K -->|"❌ 同じイベント"| RC

    RC@{ img: "../../_images/module-03/m4/rocketchat-icon.svg", label: "Rocket.Chat", pos: "b", h: 100, w: 100, constraint: "on" }
    K@{ img: "../../_images/module-03/common/kafka-icon.svg", label: "Kafka トピック", pos: "b", h: 100, w: 80, constraint: "on" }

    style RC fill:none,stroke:none
    style K fill:none,stroke:none

    linkStyle 0 stroke:#66bb6a,stroke-width:2px
    linkStyle 1 stroke:#d32f2f,stroke-width:2px,stroke-dasharray:5
----

これから定義するフィルターは、各イベントの `source` フィールドを確認し、_Rocket.Chat_ に由来するものをブロックすることでこれを防ぎます。

=== フィルターを定義する

_Kafka_ から到着するイベントは、どのソースシステムからでも発生し得ます。フィルターがないと、もともと _Rocket.Chat_ から送られたメッセージが _Kafka_ を通って再び _Rocket.Chat_ に押し戻され、ループが発生します。

  * _Rocket.Chat -> Kafka -> Rocket.Chat_ ⟵ ループバック！

{blank}

フィルターは、イベントがどこから来たかを確認することでこれを防ぎます。

[cols="3a,6a"]
|===
|
[.bordered]
[#kaoto-datamapper-configure]
image::module-03/m3/kaoto-filter-config.png[width=100%]

[.overlay]
****
[.target]
kaoto-datamapper-configure

[.numbers]
{x: 43, y: 41, size: 4}
{x: 80, y: 29, size: 4}
{x: 80, y: 86, size: 4}
****
|

1. バー pass:[<code style="background-color: #B0380C; color: white;">&nbsp;To do: Filter&nbsp;</code>] をクリックします。

1. `Required` タブが選択されていることを確認します。既定で `JQ` 式言語が選ばれているはずです。
+
{blank}
+
1. 次の式をコピーして貼り付けます。
+
{blank}
+
[.copypaste.value]
****
pass:[.source \| test("rocketchat")]
****
+
NOTE: この式は _Kafka_ イベントから `source` フィールドを取り出し、そのイベントが _Rocket.Chat_ に由来するかを確認します。_Rocket.Chat_ からのイベントは、ループバックを防ぐために除外されます。

|===

=== フローをローカルでテストする

_Camel JBang_ を使ってプロセスをバックグラウンドで実行します。

{blank}

[.copypaste]
****
labrun k2r --background
****

[TIP]
--
.このコマンドは何をしますか？
[%collapsible]
====
`labrun` は、Camel JBang を裏で実行するラボ用ヘルパーです。上のコマンドは次と同等です。

* `camel run --name k2r` — `k2r` という名前のインテグレーションを実行する
* `--source-dir k2r` — `k2r` ディレクトリからルートファイルを読み込む
* `--local-kamelet-dir ../support/kamelets` — Rocket.Chat 用を含むカスタム Kamelet（コネクタ）を読み込む
* `--background` — ターミナルで作業を続けられるようにバックグラウンドで実行する
====
--

{blank}

[.copypaste]
****
+++camel cmd send k2r --body \
'{
  "user":   "test",
  "source": "test",
  "text":   "test message"
}'+++
****

[TIP]
--
.このコマンドは何をしますか？
[%collapsible]
====
* `camel cmd send` — 実行中の Camel プロセスにメッセージを送信する
* `k2r` — 送信先プロセスの名前
* `--body '{...}'` — Kafka イベントをシミュレートする JSON ペイロード。必要なのは `user`、`source`、`text` のみです。送信先チャネルはマッピング内で固定されています。
====
--
