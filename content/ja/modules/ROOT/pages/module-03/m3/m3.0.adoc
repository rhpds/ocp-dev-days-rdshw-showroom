== はじめに

Apache Kafka を介して Matrix と Rocket.Chat をつなぐ統合フローを構築します。疎結合なイベント駆動型アーキテクチャを実現し、新しいシステムを簡単に追加できるようにします。

{empty} +


=== 簡単なおさらい

お客様は *Matrix* で保険契約の申請について問い合わせ、サポート担当者は *Rocket.Chat* から応答します。目標は、両方のプラットフォームをつなぎ、メッセージがシームレスに行き来するようにすることです。

{empty} +

=== なぜ中央に Kafka を置くのか?

Matrix と Rocket.Chat を直接つなぐのではなく、ストリーミングの基盤としてその間に *Kafka* を配置します。これにより、2 つのプラットフォームは疎結合になり、互いについて知る必要がありません。各システムは Kafka を通じてメッセージを publish、consume するだけです。

なぜこれが重要なのでしょうか? アーキテクチャを拡張しやすくなるからです。ヘルプデスクツール、通知サービス、AI エージェントなど、新しいシステムを既存のフローに手を加えることなく、同じ Kafka topic に接続できます。

=== 共通データモデル

これを円滑に機能させるため、Kafka 上の共通言語として *標準データモデル* を採用します。プラットフォーム固有の形式どうし (Matrix から Rocket.Chat へ) を直接変換するのではなく、各フローで 2 段階の変換を行います。

* *受信*: プラットフォーム固有の形式 → 標準データモデル (Kafka へ)
* *送信*: 標準データモデル → プラットフォーム固有の形式 (Kafka から)

これにより、各システムは他のすべてのシステムと個別に連携するのではなく、*1 つ* の共通インターフェースと統合するだけで済みます。

=== 4 つのフロー、1 つのパターン

Kafka を介して Matrix と Rocket.Chat を双方向につなぐには、4 つの独立したフローが必要です。

* Matrix → Kafka
* Kafka → Rocket.Chat
* Rocket.Chat → Kafka
* Kafka → Matrix

TIP: 直接接続より手間が増えたように見えるかもしれませんが、4 つすべてで同じパターンを使います。このラボでは、そのうちの *1 つ* の構築に集中します。残りも同じ手順で構築し、最後に有効化します。
