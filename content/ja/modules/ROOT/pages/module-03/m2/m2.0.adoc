== Lab 2 - メッセージングへのアクセス

このワークショップで使用する 2 つのメッセージングプラットフォーム、Matrix と Rocket.Chat について理解し、両方にログインして、これから行う統合演習に備えましょう。

{empty} +

=== メッセージングのシナリオ

Policy Application を提出したお客様は、苦情、補償内容に関する質問、既存の保険契約の変更などについて、カスタマーサポートに問い合わせる必要があるかもしれません。一方、サポート担当者はお客様を支援する準備ができています。

興味深いのは、それぞれが *異なる* メッセージングプラットフォームを使用していることです。

* *Matrix* — お客様が問い合わせを送信するために接続する場所
* *Rocket.Chat* — サポート担当者が業務を行い、問い合わせに対応する場所

[TIP]
--
.これらのプラットフォームについて
[%collapsible]
====
Matrix と Rocket.Chat は、Slack、Telegram、WhatsApp に似たメッセージングプラットフォームです。このワークショップでは、OpenShift 上にセルフホストでき、外部アカウントが不要なため、これらを使用します。

*Matrix* は、リアルタイムの分散型通信を実現するオープン標準であり、通信プロトコルです。異なるサービスプロバイダー間でもシームレスに利用できます。

*Rocket.Chat* は、厳格なデータ保護基準を備えたオープンソースのコミュニケーションプラットフォームです。Web、デスクトップ、モバイルデバイスを通じて、同僚、他社、またはお客様とのリアルタイムの会話を可能にします。
====
--

これからのモジュールでは、Apache Camel と Kafka を使用して、両方のプラットフォームをつなぐ統合を構築します。一方で送信されたメッセージが、もう一方にシームレスに表示されるようにします。
