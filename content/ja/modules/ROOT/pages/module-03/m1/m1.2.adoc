{blank}

[.bordered]
image::module-03/m1/kaoto-service-x12-route.png[width=90%]

左から右へ読むと、パイプラインの各ステップが保険申請のライフサイクルの各段階を処理していることがわかります。

* `platform-http` — 受信した保険申請を受け付ける API エンドポイント
* `transform-x12` — EDI データを XML に変換する
* `sql` — バックエンドデータベースにデータを保存する
* `store-pdf-s3` — PDF の保険文書を生成し、S3 にアップロードする

NOTE: 青い *To do: Enable* ブロックが 2 つあることに注目してください。これらは次の演習で有効化する無効状態のステップです。最終的には、フロー全体が接続され、動作するようになります。
