*操作の流れ*

以下のシーケンス図では、保険契約の申し込みを処理する際に Camel インテグレーションが実行する各手順を詳しく説明します。

{blank}

[.mermaid]
----
sequenceDiagram
    actor Customer
    participant Camel
    participant ServiceInterconnect as Service Interconnect
    participant DB@{ "type": "database", "alias": "データベース" }
    participant S3Bucket@{ "type": "collections", "alias": "S3 バケット" }
    Customer->>Camel: 保険契約の申し込みを送信 (EDI)
    Camel->>Camel: EDI を XML に変換
    Camel->>ServiceInterconnect: XML データを送信
    ServiceInterconnect->>DB: データを保存
    DB-->>ServiceInterconnect: 確認
    ServiceInterconnect-->>Camel: データを保存済み
    Camel->>Camel: XML から PDF を生成
    Camel->>S3Bucket: PDF をアップロード
    S3Bucket-->>Camel: アップロード完了
----

{blank}

[.bordered]
image::module-03/m1/kaoto-service-x12-route.png[width=90%]

左から右へ読むと、パイプラインの各ステップが保険契約の申し込みのライフサイクルにおける各段階を処理します。

* `platform-http` — 受信した保険契約の申し込みを受け付ける API エンドポイント
* `transform-x12` — EDI データを XML に変換
* `sql` — バックエンドデータベースにデータを保存
* `store-pdf-s3` — PDF の保険契約書類を生成し、S3 にアップロード

NOTE: 青色の *To do: Enable* ブロックが 2 つあることに注目してください。これらは無効になっているステップで、次の演習で有効にします。最後には、フロー全体が接続され、機能するようになります。
