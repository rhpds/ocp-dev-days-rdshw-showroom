Parasol Insuranceでのあなたの初日です。クレーム処理チームに配属され、会社のアプリケーションプラットフォームへのアクセスが与えられました。マネージャーから、Parasolアプリケーションに新しいクレーム統計APIエンドポイントを追加するよう依頼されました。これは、ビジネスがクレームのボリュームとカテゴリを追跡するのに役立つ機能です。

=== 演習 3: クレーム統計エンドポイントを追加する

次に機能を実装します。クレーム統計（合計、カテゴリとステータスごとの内訳）を返す新しいRESTエンドポイントを作成します。

. Dev Spacesに戻り、左サイドバーの**Explorer**アイコンをクリックします。ファイルツリーで、`src` -> `main` -> `java` -> `com` -> `parasol`を展開します。

. `parasol`ディレクトリを右クリックして**New File**を選択します。`ClaimsStatsResource.java`という名前を付けます。
+
完全なパスは`src/main/java/com/parasol/ClaimsStatsResource.java`である必要があります。
+
WARNING: `parasol`フォルダ内にファイルを作成してください。`com`内でも、`java`内でも、プロジェクトルートでもありません。間違った場所に作成すると、パイプラインで後でビルドとルートの失敗が発生します。
+
image::parasol-app-newfile.png[Parasol Insuranceアプリケーションダッシュボード,link=self,window=blank,width=700]

. 新しいファイルに以下のコードをコピーして貼り付けます:
+
[source,java,role="copypaste"]
----
package com.parasol;

import java.util.HashMap;
import java.util.Map;

import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    @Inject
    ClaimsResource claimsResource;

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        System.out.println("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
        }

        return stats;
    }
}
----
+
NOTE: このコードは動作しますが、いくつかのショートカットがあります。適切なロギングフレームワークの代わりに`System.out.println`を使用し、`catch`ブロックは例外を黙って飲み込みます。これらのコードの臭いは意図的です。CI/CDパイプラインがセクション4でそれらを検出します。

. kbd:[Ctrl+S]（Macの場合はkbd:[Cmd+S]）でファイルを保存します。Quarkus開発モードが変更を検出し、アプリケーションを再読み込みします。手動ビルドステップは不要です。
+
TIP: アプリケーションが自動的に再読み込みされない場合は、Dev Spacesのターミナルでコンパイルエラーを確認してください。kbd:[Ctrl+Shift+P]を押して、**Tasks: Run Task** -> **devfile** -> **Start Development Mode (Hot Reload + debug)**を選択することで、開発モードを再起動することもできます。ポートの競合が表示される場合は、最初に既存のタスクを停止してください。

. ブラウザで、Parasolアプリケーションが実行されているタブに切り替え、URLから`dashboard.html`を削除し、ブラウザのアドレスバーのURLの末尾に`/api/claims/stats`を追加します。
+
クレーム合計と内訳を含むJSONデータが表示されるはずです:
+
----
{
  "total": 15,
  "by_category": {
    "auto": 5,
    "home": 4,
    "life": 6
  },
  "by_status": {
    "open": 8,
    "closed": 7
  }
}
----
+
新しいエンドポイントが動作しています。コードを書き、ファイルを保存すると、数秒でアプリケーションが再読み込みされました。ビルドコマンドも、再パッケージ化も、再デプロイメントもありません。
+
image::parasol-claims-stats-devmode.png[開発モードでJSONデータを返すクレーム統計エンドポイント,link=self,window=blank,width=700]

=== 確認

import java.util.Map;

import io.quarkus.logging.Log;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    private final ClaimsResource claimsResource;

    public ClaimsStatsResource(ClaimsResource claimsResource) {
        this.claimsResource = claimsResource;
    }

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        Log.info("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
            Log.error("Error fetching claim statistics", e);
        }

        return stats;
    }
}

== モジュールサマリー

Parasol Insuranceでの完全な開発者ジャーニーを完了しました。オンボーディングから本番デプロイメントまで、チケットを1つも提出せず、ツールをインストールせず、誰かを待つこともありませんでした。

**達成したこと:**

* Developer Hubのソフトウェアカタログを通じてアプリケーション、API、ドキュメントを発見
* Lightspeedを使用してプラットフォームに関するAI駆動の回答を取得
* セルフサービステンプレートで分離された開発環境を作成
* Dev Spacesを使用して事前設定されたクラウドIDEでコードを記述およびテスト
* AIコーディングアシスタントを使用してコード品質の問題を修正
* 品質ゲートを備えた自動化されたCI/CDパイプラインを通じてコードをプッシュ
* リリースタグを作成し、GitOpsプロモーションを承認して本番環境にデプロイ
* Developer Hubのトポロジービューを通じて本番環境で機能を確認

**重要なポイント:**

* **Developer Hub**は単一のガラス窓です -- カタログ、テンプレート、CI/CD可視性、AI支援が1か所にあります
* **Dev Spaces**はローカル環境のセットアップを排除します -- すべての開発者が同じ事前設定されたワークスペースを取得します
* **Pipelines**は品質を自動的に実施します -- コードの臭いとセキュリティの問題は本番環境の前に検出されます
* **GitOps**はデプロイメントを繰り返し可能で監査可能にします -- Gitは単一の真実の情報源です
* **プラットフォーム**は差別化されていない重労働を処理するため、開発者はコードの記述に集中できます

これが統合されたアプリケーションプラットフォームの姿です。コードから本番環境まで必要なものすべてが、オンプレミス、あらゆるクラウド、またはエッジで利用可能です。
