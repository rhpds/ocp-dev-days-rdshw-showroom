=== 演習 3: 請求統計エンドポイントを追加する

いよいよ機能を実装します。請求統計（合計、カテゴリ別、ステータス別の内訳）を返す新しい REST エンドポイントを作成します。

. Dev Spaces に戻り、左サイドバーの **Explorer** アイコンをクリックします。ファイルツリーで `src` -> `main` -> `java` -> `com` -> `parasol` を展開します。

. `parasol` ディレクトリを右クリックし、**New File** を選択します。ファイル名を `ClaimsStatsResource.java` にします。
+
完全なパスは `src/main/java/com/parasol/ClaimsStatsResource.java` でなければなりません。
+
WARNING: `parasol` フォルダの中にファイルを作成してください -- `com` でも `java` でもなく、プロジェクトルートでもありません。間違った場所に作成すると、後のパイプラインでビルドやルートの失敗につながります。
+
image::parasol-app-newfile.png[Parasol Insurance アプリケーションのダッシュボード,link=self,window=blank,width=700]

. 次のコードを新しいファイルにコピーして貼り付けます:
+
[source,java,role="copypaste"]
----
package com.parasol;

import java.util.HashMap;
import java.util.Map;

import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    @Inject
    ClaimsResource claimsResource;

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        System.out.println("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
        }

        return stats;
    }
}
----
+
NOTE: このコードは動作しますが、いくつか簡略化されています。`System.out.println` を適切な logging framework の代わりに使っており、`catch` ブロックは例外を黙って飲み込んでいます。これらの code smell は意図的なものです -- CI/CD パイプラインが第 4 セクションで検出します。

. kbd:[Ctrl+S]（Mac では kbd:[Cmd+S]）でファイルを保存します。Quarkus の dev mode が変更を検知してアプリケーションを再読み込みします -- 手動のビルド手順は不要です。
+
TIP: アプリケーションが自動で再読み込みされない場合は、Dev Spaces のターミナルでコンパイルエラーを確認してください。kbd:[Ctrl+Shift+P] を押して **Tasks: Run Task** -> **devfile** -> **Start Development Mode (Hot Reload + debug)** を選び、dev mode を再起動することもできます。ポート競合が出た場合は、先に既存のタスクを停止してください。

. ブラウザーで、実行中の Parasol アプリケーションのタブに切り替え、URL から `dashboard.html` を削除して、ブラウザーのアドレスバーの末尾に `/api/claims/stats` を追加します。
+
請求件数の合計と内訳を含む JSON データが表示されるはずです:
+
----
{
  "total": 15,
  "by_category": {
    "auto": 5,
    "home": 4,
    "life": 6
  },
  "by_status": {
    "open": 8,
    "closed": 7
  }
}
----
+
新しいエンドポイントは動作しています。コードを書き、ファイルを保存すると、アプリケーションは数秒で再読み込みされました。ビルドコマンドも、再パッケージも、再デプロイもありません。
+
image::parasol-claims-stats-devmode.png[開発モードで JSON データを返す請求統計エンドポイント,link=self,window=blank,width=700]

package com.parasol;

import java.util.HashMap;
import java.util.Map;

import io.quarkus.logging.Log;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    private final ClaimsResource claimsResource;

    public ClaimsStatsResource(ClaimsResource claimsResource) {
        this.claimsResource = claimsResource;
    }

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        Log.info("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
            Log.error("Error fetching claim statistics", e);
        }

        return stats;
    }
}

== モジュールのまとめ

Parasol Insurance での開発者としての一連の流れを、オンボーディングから本番デプロイまで、チケットを 1 枚も起票せず、ツールを 1 つもインストールせず、誰かを待つこともなく完了しました。

**達成したこと:**

* Developer Hub のソフトウェアカタログを通じてアプリケーション、API、ドキュメントを見つけた
* Lightspeed を使ってプラットフォームに関する AI の回答を得た
* セルフサービステンプレートで分離された開発環境を作成した
* Dev Spaces の事前設定済みクラウド IDE でコードを書き、テストした
* AI コーディングアシスタントを使ってコード品質の問題を修正した
* 品質ゲート付きの自動 CI/CD パイプラインを通してコードを push した
* リリースタグを作成し、GitOps 昇格を承認して本番にデプロイした
* Developer Hub のトポロジービューで本番の機能を確認した

**重要なポイント:**

* **Developer Hub** は単一の統合ビューです -- カタログ、テンプレート、CI/CD の可視化、AI 支援がすべて一か所にあります
* **Dev Spaces** はローカル環境のセットアップを不要にします -- すべての開発者に同じ事前設定済みワークスペースが提供されます
* **Pipelines** は品質を自動で強制します -- code smell やセキュリティ問題は本番前に検出されます
* **GitOps** はデプロイを再現可能かつ監査可能にします -- Git が唯一の信頼できるソースです
* **プラットフォーム** が差別化されない重労働を担うので、開発者はコードを書くことに集中できます

これが、一貫性のあるアプリケーションプラットフォームの姿です。コードから本番まで、必要なものはすべて、オンプレミスでも、あらゆるクラウドでも、エッジでも利用できます。
