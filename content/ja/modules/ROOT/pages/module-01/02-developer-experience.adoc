=== 演習 3: 保険金請求統計エンドポイントを追加する

機能を実装しましょう。保険金請求統計 (合計、カテゴリー別およびステータス別の内訳) を返す新しいRESTエンドポイントを作成します。

. Dev Spacesに戻り、左サイドバーの **Explorer** アイコンをクリックします。ファイルツリーで `src` -> `main` -> `java` -> `com` -> `parasol` の順に展開します。

. `parasol` ディレクトリーを右クリックして **New File** を選択します。ファイル名を `ClaimsStatsResource.java` にします。
+
フルパスは `src/main/java/com/parasol/ClaimsStatsResource.java` でなければなりません。
+
WARNING: ファイルは `com` や `java` の中、またはプロジェクトルートではなく、必ず `parasol` フォルダー内に作成してください。誤った場所に作成すると、後のパイプラインでビルドやRouteに失敗します。
+
image::parasol-app-newfile.png[Parasol Insuranceアプリケーションのダッシュボード,link=self,window=blank,width=700]

. 次のコードを新しいファイルにコピーして貼り付けます:
+
[source,java,role="copypaste"]
----
package com.parasol;

import java.util.HashMap;
import java.util.Map;

import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    @Inject
    ClaimsResource claimsResource;

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        System.out.println("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
        }

        return stats;
    }
}
----
+
NOTE: このコードは動作しますが、いくつか簡略化されています。適切なロギングフレームワークの代わりに `System.out.println` を使い、`catch` ブロックでは例外を黙って無視しています。これらのコードスメルは意図的なもので、セクション 4 でCI/CDパイプラインが検出します。

. kbd:[Ctrl+S] (Macでは kbd:[Cmd+S]) を押してファイルを保存します。Quarkusの開発モードが変更を検出し、アプリケーションを再読み込みします。手動でビルドする必要はありません。
+
TIP: アプリケーションが自動的に再読み込みされない場合は、Dev Spacesのターミナルでコンパイルエラーを確認してください。kbd:[Ctrl+Shift+P] を押して **Tasks: Run Task** -> **devfile** -> **Start Development Mode (Hot Reload + debug)** を選択し、開発モードを再起動することもできます。ポート競合が表示された場合は、まず既存のタスクを停止してください。

. ブラウザーでParasolアプリケーションが実行されているタブに切り替え、URLから `dashboard.html` を削除して、ブラウザーのアドレスバーの末尾に `/api/claims/stats` を追加します。
+
請求件数と内訳を含むJSONデータが表示されるはずです:
+
----
{
  "total": 15,
  "by_category": {
    "auto": 5,
    "home": 4,
    "life": 6
  },
  "by_status": {
    "open": 8,
    "closed": 7
  }
}
----
+
新しいエンドポイントが動作しています。コードを書いてファイルを保存すると、数秒でアプリケーションが再読み込みされました。ビルドコマンドも、再パッケージも、再デプロイも必要ありません。
+
image::parasol-claims-stats-devmode.png[開発モードでJSONデータを返す保険金請求統計エンドポイント,link=self,window=blank,width=700]

package com.parasol;

import java.util.HashMap;
import java.util.Map;

import io.quarkus.logging.Log;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api/claims/stats")
@Produces(MediaType.APPLICATION_JSON)
public class ClaimsStatsResource {

    private final ClaimsResource claimsResource;

    public ClaimsStatsResource(ClaimsResource claimsResource) {
        this.claimsResource = claimsResource;
    }

    @GET
    public Map<String, Object> getStats() {
        Map<String, Object> stats = new HashMap<>();

        Log.info("Fetching claim statistics");

        try {
            var claims = claimsResource.getAllClaims();
            stats.put("total", claims.size());

            Map<String, Long> byCategory = new HashMap<>();
            for (var claim : claims) {
                byCategory.merge(claim.getCategory(), 1L, Long::sum);
            }
            stats.put("by_category", byCategory);

            Map<String, Long> byStatus = new HashMap<>();
            for (var claim : claims) {
                byStatus.merge(claim.getStatus(), 1L, Long::sum);
            }
            stats.put("by_status", byStatus);
        } catch (Exception e) {
            Log.error("Error fetching claim statistics", e);
        }

        return stats;
    }
}

== モジュールのまとめ

チケットを一枚も申請せず、ツールをインストールせず、誰かを待つこともなく、Parasol Insuranceでの開発者の一連の作業をオンボーディングから本番デプロイまで完了しました。

**達成したこと:**

* Developer Hubのソフトウェアカタログを通じて、アプリケーション、API、ドキュメントを見つけた
* Lightspeedを使って、プラットフォームに関するAI支援の回答を得た
* セルフサービステンプレートで分離開発環境を作成した
* Dev Spacesを備えた事前設定済みのクラウドIDEでコードを書き、テストした
* AIコーディングアシスタントを使ってコード品質の問題を修正した
* 品質ゲートを備えた自動CI/CDパイプラインにコードをプッシュした
* リリースタグを作成し、GitOpsによる本番環境への昇格を承認した
* Developer Hubのトポロジービューで本番環境の機能を確認した

**重要なポイント:**

* **Developer Hub** は単一の管理画面です。カタログ、テンプレート、CI/CDの可視化、AI支援を1か所で提供します
* **Dev Spaces** によりローカル環境のセットアップが不要になります。すべての開発者が同じ事前設定済みワークスペースを利用できます
* **Pipelines** は品質を自動的に徹底します。コードスメルやセキュリティ上の問題が本番環境に到達する前に検出されます
* **GitOps** によって、再現性があり監査可能なデプロイが実現します。Gitが唯一の信頼できる情報源です
* **プラットフォーム** が差別化につながらない煩雑な作業を担うため、開発者はコードの作成に集中できます

これが、統合されたアプリケーションプラットフォームの姿です。コードから本番環境まで、必要なものすべてをオンプレミス、あらゆるクラウド、またはエッジで利用できます。
