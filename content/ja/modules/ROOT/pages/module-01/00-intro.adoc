= モジュール 1: 開発者体験
include::partial$_attributes.adoc[]

== 学習内容

このワークショップでは、次のことを体験します。

* Red Hat Developer Hub をセルフサービス型の社内開発者ポータルとして活用する
* ソフトウェアカタログでアプリケーション、API、ドキュメントを見つける
* Red Hat OpenShift Dev Spaces で事前設定済みのクラウド開発環境を起動する
* AI コーディングアシスタントを使って機能を実装する
* OpenShift Pipelines を使い、自動化された CI/CD パイプラインでコードを push する
* Red Hat OpenShift GitOps (Argo CD) を使い、GitOps で本番環境へデプロイする
* Developer Hub と OpenShift Console からアプリケーションをデバッグし、監視する

== このワークショップの対象者

このワークショップは、OpenShift がコードから本番環境まで一貫して提供する開発者体験を理解したい開発者、プラットフォームエンジニア、IT 意思決定者向けに設計されています。

**経験レベル** : 初級〜中級。OpenShift の事前知識は不要です。

== 所要時間

このワークショップの所要時間は約 **90 分** です。

自分のペースで進められます。

== あなたの役割とミッション

あなたは **Parasol Insurance** の新しい開発者です。

Parasol は急成長しています。新しい製品ライン、新しいチーム、新しい開発者が次々と増えていますが、プラットフォームチームは対応しきれていません。新しいチームを立ち上げるたびに、専用の CI/CD 設定や namespace のプロビジョニングが必要で、オンボーディングにも数週間かかります。開発者はコードを書くよりも、チケットを起票してアクセス権を待つことに多くの時間を費やしています。ローカル環境は頻繁に壊れたり、設定にずれが生じたりして、生産性が落ちています。短期間だけ参加する契約開発者は、必要な情報やベストプラクティスを見つけるのに苦労しています。

身に覚えがありますか？

Parasol のプラットフォームエンジニアリングチームは、解決策として、Red Hat OpenShift 上に一貫性のあるアプリケーションプラットフォームを構築してきました。開発者向けツール、CI/CD、GitOps によるデプロイ、セルフサービス型の社内開発者ポータルを、すべて 1 か所で提供します。

**今日はあなたの初出勤日です。** プラットフォームへのアクセス権が与えられ、最初のタスクが割り当てられました。このワークショップを終えるころには、チケットを 1 件も起票せずに機能を本番環境へリリースできるようになります。

== できるようになること

このワークショップの終了時には、次の項目を実際に体験できます。

* **Red Hat Developer Hub** -- ソフトウェアカタログを操作して API やドキュメントを見つけ、AI アシスタントにプラットフォームについて質問する
* **セルフサービステンプレート** -- ゴールデンパステンプレートを使い、専用の CI/CD パイプラインを備えた独立した開発環境を作成する
* **Red Hat OpenShift Dev Spaces** -- ローカルに何もインストールせず、AI コーディングアシスタントを備えた設定済みのクラウド IDE でコードを書く
* **OpenShift Pipelines** -- コードを push し、自動化された CI/CD パイプラインで変更がビルド、テスト、スキャンされる様子を確認する
* **OpenShift GitOps** -- Argo CD が変更を本番環境へ自動でデプロイする様子を確認する
* **OpenShift Console** -- Web コンソールで、より詳しくデバッグし、アプリケーションを監視する

== 開発者の流れ

このワークショップでは、ひとつながりのストーリーに沿って進みます。

. **プラットフォームを知る** -- Developer Hub にログインし、ソフトウェアカタログを確認して、プラットフォームの概要をつかむ
. **あなたのミッション** -- 割り当てられたタスクを見つけ、開発環境をセットアップする
. **機能を実装する** -- Dev Spaces を開いてコードを書き、ローカルでテストする
. **リリースする** -- CI/CD パイプラインにコードを流し、品質ゲートを通過する
. **AI の力を借りる** -- エージェント型 AI アシスタントを使ってコードを修正し、もう一度 push してパイプラインを通過する
. **本番へ出す** -- 変更をマージし、リリースを作成し、本番環境で機能を確認する

ツールごとにコンテキストを切り替える必要はありません。アイデアから本番環境まで、一貫した流れで進められます。

== 対象読者

このワークショップは、次のような方を対象としています。

* より速く、一貫した開発ワークフローを求めるソフトウェア開発者
* アプリケーションプラットフォームの機能を評価する IT 意思決定者
* 自分たちが提供する開発者体験を理解したいプラットフォームエンジニア
* OpenShift の開発者向けツールを実際に使ってみたい方

== 前提条件

次の条件を満たしている必要があります。

* Web アプリケーションと API の基本的な知識
* Web ブラウザーとコードエディターを使えること
* 学ぶ意欲があること -- OpenShift やコンテナの事前経験は不要です
