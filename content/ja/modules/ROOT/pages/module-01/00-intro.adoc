= モジュール 1: 開発者エクスペリエンス
include::partial$_attributes.adoc[]

== 学習内容

このワークショップでは、以下を学習します:

* セルフサービス型の社内開発者ポータルとしてのRed Hat Developer Hubの探索
* ソフトウェアカタログを使用したアプリケーション、API、ドキュメントの発見
* Red Hat OpenShift Dev Spacesを使用した事前設定されたクラウド開発環境の起動
* AIコーディングアシスタントを使用した機能の構築
* OpenShift Pipelinesを使用した自動化されたCI/CDパイプラインへのコードのプッシュ
* Red Hat OpenShift GitOps (Argo CD)を使用したGitOpsによる本番デプロイメント
* Developer HubとOpenShift Consoleからのアプリケーションのデバッグと監視

== 対象者

このワークショップは、OpenShiftが提供する統合された開発者エクスペリエンス（コードから本番環境まで）を理解したい開発者、プラットフォームエンジニア、IT意思決定者を対象としています。

**経験レベル**: 初級から中級。OpenShiftの事前経験は不要です。

== 所要時間

このワークショップの完了には約**90分**かかります。

ご自身のペースで進めてください。

== あなたの役割とミッション

あなたは**Parasol Insurance**の新しい開発者です。

Parasolは急速に成長しています。新しい製品ライン、新しいチーム、新しい開発者 — しかしプラットフォームチームは追いつけません。新しいチームごとにカスタムCI/CDセットアップ、独自の名前空間プロビジョニング、数週間にわたるオンボーディングプロセスが必要です。開発者はコードを書くよりも、チケットを提出してアクセスを待つことに多くの時間を費やしています。ローカル環境は頻繁に壊れたり、ずれたりして、生産性が失われます。時々オンボーディングする契約社員は、関連情報とベストプラクティスを見つけるのに長い時間がかかります。

聞き覚えがありますか？

Parasolのプラットフォームエンジニアリングチームは、解決策に取り組んできました: Red Hat OpenShift上に構築された統合アプリケーションプラットフォームで、開発者ツール、CI/CD、GitOps駆動のデプロイメント、セルフサービス型の社内開発者ポータルをすべて1か所で提供します。

**今日はあなたの初日です。** プラットフォームへのアクセスが与えられ、最初のタスクが割り当てられました。このワークショップの終わりまでに、チケットを1つも提出することなく、本番環境に機能をデプロイすることになります。

== 達成すること

このワークショップの終わりまでに、以下の実践経験を得られます:

* **Red Hat Developer Hub** — ソフトウェアカタログのナビゲーション、APIとドキュメントの発見、AIアシスタントを使用したプラットフォームに関する回答の取得
* **セルフサービステンプレート** — ゴールデンパステンプレートを使用した、独自のCI/CDパイプラインを持つ分離された開発環境の作成
* **Red Hat OpenShift Dev Spaces** — ローカルに何もインストールせずに、AIコーディングアシスタントを備えた事前設定されたクラウドIDEでコードを記述
* **OpenShift Pipelines** — コードをプッシュし、自動化されたCI/CDパイプラインが変更をビルド、テスト、スキャンするのを確認
* **OpenShift GitOps** — Argo CDが変更を自動的に本番環境にデプロイするのを確認
* **OpenShift Console** — Webコンソールを使用した、より詳細なデバッグとアプリケーション監視

== 開発者ジャーニー

このワークショップは1つの連続したストーリーに従います:

. **プラットフォームを知る** — Developer Hubにログインし、ソフトウェアカタログを探索し、方向を確認
. **あなたのミッション** — 割り当てられたタスクを見つけ、開発環境をセットアップ
. **機能を構築する** — Dev Spacesを開き、コードを書き、ローカルでテスト
. **デプロイする** — コードをCI/CDパイプラインにプッシュし、品質ゲートに到達
. **AIを呼び出す** — エージェンティックAIアシスタントを使用してコードを修正し、再度プッシュし、パイプラインを通過
. **本番稼働する** — 変更をマージし、リリースを作成し、本番環境で機能を検証

切断されたツール間のコンテキストスイッチングはありません。アイデアから本番環境まで1つの連続したフロー。

== 対象読者

このワークショップは以下の方を対象としています:

* より高速で一貫性のある開発ワークフローを求めるソフトウェア開発者
* アプリケーションプラットフォーム機能を評価するIT意思決定者
* 実現する開発者エクスペリエンスを理解したいプラットフォームエンジニア
* OpenShiftの開発者ツールの実践経験に興味がある方

== 前提条件

以下が必要です:

* Webアプリケーションとa APIに関する基本的な知識
* Webブラウザとコードエディタの使用に慣れていること
* 学習する意欲 — OpenShiftまたはコンテナの事前経験は不要
