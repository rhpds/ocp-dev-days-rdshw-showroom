= モジュール 1: 開発者体験

== 学習内容

このワークショップでは、次のことを学びます。

* Red Hat Developer Hub をセルフサービス型の社内開発者ポータルとして活用する
* ソフトウェアカタログを使って、アプリケーション、API、ドキュメントを見つける
* Red Hat OpenShift Dev Spaces を使って、事前設定済みのクラウド開発環境を起動する
* AI コーディングアシスタントを使って機能を実装する
* OpenShift Pipelines を使って、自動化された CI/CD パイプラインでコードを送信する
* Red Hat OpenShift GitOps (Argo CD) を使った GitOps で本番環境へデプロイする
* Developer Hub と OpenShift Console からアプリケーションをデバッグし、監視する

== このワークショップの対象者

このワークショップは、OpenShift が提供する一貫した開発者体験を、コードから本番環境まで通して理解したい開発者、プラットフォームエンジニア、IT 意思決定者向けに設計されています。

**経験レベル**: 初級から中級。OpenShift の事前知識は不要です。

== 所要時間

このワークショップの所要時間は約 **90 分** です。

自分のペースで進められます。

== あなたの役割とミッション

あなたは **Parasol Insurance** の新任開発者です。

Parasol は急速に成長しています。新しい製品ライン、新しいチーム、新しい開発者が増えていますが、プラットフォームチームは追いつけていません。新しいチームごとに独自の CI/CD 設定、独自の namespace プロビジョニング、そして数週間に及ぶオンボーディングプロセスが必要です。開発者はコードを書くよりも、チケットを起票してアクセスを待つことに多くの時間を費やしています。ローカル環境は頻繁に壊れたり、構成がずれたりして、生産性の低下を招きます。ときどき参加する委託開発者は、関連情報やベストプラクティスを見つけるのに長い時間がかかります。

身に覚えがありますか？

Parasol のプラットフォームエンジニアリングチームは、解決策に取り組んできました。それは、Red Hat OpenShift 上に構築された一貫性のあるアプリケーションプラットフォームで、開発者向けツール、CI/CD、GitOps 駆動のデプロイ、セルフサービス型の社内開発者ポータルを 1 か所にまとめて提供するものです。

**今日はあなたの初出勤日です。** プラットフォームへのアクセスが付与され、最初のタスクが割り当てられました。このワークショップが終わるころには、1 件のチケットも起票せずに機能を本番環境へリリースできるようになります。

== できるようになること

このワークショップの終了時には、次の項目を実際に体験できます。

* **Red Hat Developer Hub** -- ソフトウェアカタログを操作し、API とドキュメントを見つけ、AI アシスタントを使ってプラットフォームに関する回答を得る
* **セルフサービステンプレート** -- ゴールデンパスのテンプレートを使い、独自の CI/CD パイプラインを備えた分離された開発環境を作成する
* **Red Hat OpenShift Dev Spaces** -- ローカルに何もインストールせず、AI コーディングアシスタント付きの事前設定済みクラウド IDE でコードを書く
* **OpenShift Pipelines** -- コードを push し、自動化された CI/CD パイプラインが変更をビルド、テスト、スキャンする様子を確認する
* **OpenShift GitOps** -- Argo CD が変更を本番環境へ自動的にデプロイする様子を見る
* **OpenShift Console** -- Web コンソールを使って、より詳細なデバッグとアプリケーション監視を行う

== 開発者の流れ

このワークショップは、ひとつながりのストーリーに沿って進みます。

. **プラットフォームに触れる** -- Developer Hub にログインし、ソフトウェアカタログを確認して、全体像をつかむ
. **あなたのミッション** -- 割り当てられたタスクを見つけ、開発環境をセットアップする
. **機能を実装する** -- Dev Spaces を開き、コードを書き、ローカルでテストする
. **リリースする** -- CI/CD パイプラインにコードを流し、品質ゲートを通過する
. **AI を呼ぶ** -- エージェント型 AI アシスタントを使ってコードを修正し、もう一度 push してパイプラインを通過する
. **本番へ出す** -- 変更をマージし、リリースを作成し、本番環境で機能を確認する

分断されたツール間でコンテキストを切り替える必要はありません。アイデアから本番環境まで、一続きの流れで進められます。

== 対象読者

このワークショップは、次のような方を対象としています。

* より速く、一貫性のある開発ワークフローを求めるソフトウェア開発者
* アプリケーションプラットフォームの機能を評価している IT 意思決定者
* 自分たちが実現する開発者体験を理解したいプラットフォームエンジニア
* OpenShift の開発者向けツールを実際に体験したい方

== 前提条件

次の条件を満たしている必要があります。

* Web アプリケーションと API に関する基本的な知識があること
* Web ブラウザーとコードエディターの使用に慣れていること
* 学ぶ意欲があること -- OpenShift やコンテナの事前経験は不要です
