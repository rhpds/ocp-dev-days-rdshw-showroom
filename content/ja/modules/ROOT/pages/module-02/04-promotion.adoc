サンドボックスの image はクリーンな状態です -- 脆弱性に対処し、ベース image を強化し、commit に署名しました。ここから、merge request check、マージ後の build、本番環境への tag ベースの promotion という、セキュリティで保護された pipeline の各ステージに変更を進めます。

サンドボックスとは異なり、これらの pipeline ではセキュリティポリシーが **適用** されます。署名されていない commit、ポリシー違反、承認の不足があると、promotion はブロックされます。

+
image::m02-gitlab-mr-pipeline-running.png[マージがブロックされた状態で実行中の MR check pipeline,link=self,window=blank,width=700]

. GitLab で pipeline の表示を開き、task のいずれかをクリックします。Developer Hub で MR Check Pipeline Run が開きます。
+
image::m02-gitlab-mr-pipeline-jobs.png[commit の検証と ACS の job を表示する GitLab MR pipeline,link=self,window=blank,width=700]

. component を確認してください。サンドボックスではなく、`Parasol Insurance (Secured)` になっています。
+
image::m02-rhdh-mr-check-pipeline.png[Developer Hub の Parasol Insurance Secured 上で実行される MR check pipeline,link=self,window=blank,width=700]

. MR check pipeline では次の処理が行われます:
* **commit 署名を検証** -- `ENFORCE=true` の場合、署名されていない commit は **pipeline が失敗します**
* MR branch から image を **build**
* ACS ポリシーに照らして image を **スキャンしてチェック**
* commit status と詳細な MR コメントとして、結果を GitLab に **報告**

. pipeline が完了するまで待ちます。

. GitLab の merge request ページに戻ります。
* 「Merge」ボタンが有効になり、マージできる状態です。ただし、その前に確認します。
* 下にスクロールし、Activity の最新項目を確認します。署名 status、ACS ポリシーの結果、脆弱性数が記載された **🔀 Merge Request Check Results** コメントが投稿されています。
* pre-check が成功した場合、特に確認することはありません。問題が起きた場合の内容と修正方法を確認するほうが重要です。今回は成功しているので、参考情報として確認してください。
+
image::m02-gitlab-mr-ready-to-merge.png[pipeline が成功し、マージ可能になった merge request,link=self,window=blank,width=700]
+
image::m02-gitlab-mr-results.png[署名と ACS の検証結果を示す merge request check の結果,link=self,window=blank,width=700]

=== 演習 3: Merge Request をマージする

. すべてのチェックに合格すると、 **Merge** ボタンが使用可能になります。
+
NOTE: pipeline が失敗した場合 (署名されていない commit など)、マージはブロックされます。これを適用するため、GitLab は `onlyMergeWhenPipelineSucceeds` で設定されています。

. **Merge** をクリックします。
+
これにより **マージ後の build pipeline** が開始されます。`main` から **__最終 image__** が build され、Tekton Chains によって署名と attestation が付与され、Quay に保存された後、preprod 環境に deploy されます。
+
image::m02-rhdh-post-merge-pipeline.png[Developer Hub のマージ後 build pipeline,link=self,window=blank,width=700]

== セクション 2: 本番環境への promotion

マージ後の build では、`main` branch から署名済み image が作成されました。本番環境に promotion するには **Git tag** を作成します。これにより tag-promote pipeline が開始されます。

=== 演習 1: tag を作成する

. GitLab で **Repository** → **Tags** に移動します。

. **New tag** をクリックします。

. tag 名 (例: `v2.0`) を入力し、source として `main` branch を選択します。
+
image::m02-gitlab-create-tag.png[GitLab での tag の作成,link=self,window=blank,width=700]

. **Create tag** をクリックします。

=== 演習 2: tag-promote pipeline を確認する

* image の attestation に対して **Conforma/Enterprise Contract の検証** を実行
* **SBOM** を生成し、TPA にアップロード
* registry 内の tag 付き version に image をコピー
* production deployment を更新するため、GitOps manifests repository に **merge request** を作成

. Developer Hub で **Parasol Insurance (Secured)** component に移動し、 **CI** タブをクリックします。
+
`parasol-insurance-secured-tag-promote` pipeline の実行を探します。

=== 演習 3: Conforma のポリシー違反を理解する

. **Conforma (ec)** の検証では、image の署名済み attestation を一連のポリシーに照らしてチェックします。次の結果が表示されます:
* ✅ **Image signature check** -- image は Tekton Chains によって署名されています
* ✅ **Attestation signature check** -- attestation は署名され、有効です
* ✅ **Commit must be signed** -- SLSA attestation によって commit が署名済みであることが証明されています
* ✅ **ACS checks passed** -- image scan とポリシーチェックの結果が attestation に含まれています
* ✅ **SonarQube quality gate** -- code quality の指標が attestation に含まれています
* ❌ **Parasol Release Approved** -- リリース承認の attestation が見つかりません
+


. image がリリース承認されていないため、pipeline は正しく promotion をブロックします。image に **リリース承認の署名済み attestation** が付与されていません。

=== これが重要な理由

本番環境に deploy された image には、完全な **SLSA provenance chain** が付与されています:

* **署名済み commit** -- 検証済みの開発者 ID まで追跡可能
* **SLSA attestation** -- build pipeline が実行されたこと、実行された task、およびその結果を証明
* **ACS scan の結果** -- 脆弱性評価が attestation に組み込まれている
* **SonarQube の結果** -- code quality の指標が attestation に含まれている
* **署名済み承認** -- リリースに対する明示的な人間の承認
* **SBOM** -- image 内の component の完全な一覧。継続的な脆弱性の照合に使うため、TPA に保存されます

これは単なるチェックボックスを埋める作業ではありません。すべての証拠は暗号学的に署名され、個別に検証できます。

[%collapsible]
====
**Tekton Chains** は Sigstore の keyless signing を使って、pipeline artifact に自動で署名します:

* pipeline の実行ごとに、Chains は pipeline service account の ID を使って **Fulcio** に有効期間の短い証明書を要求します
* すべての task 結果を含む **SLSA provenance attestation** を作成します
* attestation と署名は **Rekor** (透明性ログ) に記録され、registry 内の image に付与されます

**Conforma (Enterprise Contract)** は、{gitlab_url}/parasol/conforma-policies[`conforma-policies` GitLab repository^] に格納された一連の Rego ポリシーに照らして attestation を検証します。`parasol-software-supply-chain` bundle のポリシーでは、次の項目をチェックします:

* 必須の task が実行されている (verify-commit-signature、acs-image-scan、acs-image-check、sonar-scan)
* commit の署名 status が `SIGNED` (未署名または bot による commit ではない)
* ACS のポリシーチェックに合格している
* SonarQube quality gate に合格している
* image に署名済みのリリース承認 attestation がある

image::m02-gitlab-conforma-policies.png[GitLab の Conforma policies repository,link=self,window=blank,width=700]

**承認 attestation** は、predicate type `https://parasol-insurance.com/releases/v1` を使うカスタム in-toto attestation です。承認者の ID によって (Fulcio 経由で) 署名され、Chains attestation とともに image に付与されます。

現在 production にある image に関連付けられた署名済み attestation を調べるには、**Release Approval** アプリに戻ります (Developer Hub の **Parasol Insurance (Secured)** component から開きます):

image::m02-rhdh-release-approval-link.png[Parasol Insurance Secured component の Release Approval リンク,link=self,window=blank,width=400]

tag をクリックすると、その image に関連付けられた署名済み attestation を確認できます:

image::m02-approval-inspect-attestations.png[tag をクリックして attestation を確認,link=self,window=blank,width=500]

ここでは、カスタム attestation の署名者 ID と、Tekton Chains によって署名された自動生成の attestation を確認できます:

image::m02-approval-attestation-details.png[Release Approval と SLSA Provenance、および署名者 ID を示す attestation の詳細,link=self,window=blank,width=700]

**Attestation Detail** セクションでは、image に保存された attestation を確認できます:

image::m02-approval-attestation-json.png[predicate と subject を含む in-toto statement を表示する Attestation Detail,link=self,window=blank,width=700]

**SBOM** は **syft** を使って生成され、開発者と version tag を識別する label とともに TPA にアップロードされます。TPA は SBOM を取り込まれた脆弱性データと継続的に照合し、deploy 済み image のセキュリティ状況を継続的に可視化します。

=== 確認

この時点で、次の作業が完了しているはずです:

* 署名済み MR をマージし、マージ後の build が成功することを確認した
* tag を作成し、承認不足によって tag-promote pipeline が失敗することを確認した
* リリースを承認し、Conforma の検証に合格したことを確認した
* 完全な SLSA provenance chain を備えた production deployment を検証した
