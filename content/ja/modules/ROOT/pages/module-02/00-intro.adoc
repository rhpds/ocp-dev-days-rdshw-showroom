== 学習内容

このモジュールでは、次の内容を学びます。

* 開発ライフサイクルの各段階にセキュリティガードレールがどのように組み込まれているかを理解する
* Red Hat Dependency Analytics を使用して、脆弱性がパイプラインに到達する前に特定して修正する
* Sigstore のキーレス署名を使用して、自分の ID でコミットに署名する
* 自動化されたパイプラインが署名を検証し、イメージをスキャンし、ポリシーを適用する様子を確認する
* マージリクエストのチェック、Conforma/Enterprise Contract による検証、署名付き承認プロセスを経てリリースを昇格させる
* Sigstore Policy Controller が名前空間レベルで未承認のデプロイメントをどのように防ぐかを確認する

== 対象者

このモジュールでは、セキュリティの観点から開発およびリリースプロセスを見ていきます。コードから本番環境に至るまで、従来の開発ワークフローに各段階でセキュリティガードレールを追加する方法を理解したい開発者、セキュリティエンジニア、プラットフォームエンジニアを対象としています。

**経験レベル**: 中級。Git、CI/CD パイプライン、コンテナーイメージの知識があると役立ちます。

== 所要時間

このモジュールの完了には約 **60～90 分** かかります。

== あなたの役割とミッション

あなたは **Parasol Insurance** の開発者です。日々使用する開発ワークフロー（コーディング、コミット、ビルド、デプロイ）には、プラットフォームチームによってセキュリティガードレールが追加されています。アプリケーションの脆弱性を修正し、強化されたプロセスを通して変更をリリースし、各セキュリティ制御について学ぶことがあなたの仕事です。

Parasol の CISO オフィスは、すべての本番環境へのデプロイメントに次の要件を定めています。

* 検証済みの開発者 ID に追跡可能な **署名付きコミット** からビルドされていること
* 昇格前に **脆弱性スキャン** と **ポリシーチェック** に合格すること
* ビルドパイプラインが正しく実行されたことを証明する **署名付きアテステーション** を含むこと
* 本番環境に到達する前に **明示的な承認** を受けること
* デプロイ時に **アドミッションコントローラー** によって検証されること



== セキュアな開発の流れ

このモジュールでは、一連のストーリーに沿って進めます。

. **プラットフォームを知る** -- Developer Hub のセキュアなコンポーネントを確認し、分離されたサンドボックスを作成する
. **脆弱性対応を早期化する** -- Dependency Analytics を使用して、脆弱性がパイプラインに到達する前に発見して修正する
. **コミットに署名する** -- Sigstore のキーレス署名を使用して、各コミットを自分の ID に紐付ける
. **サンドボックスパイプライン** -- 自動チェックで署名を検証し、イメージをスキャンし、ACS ポリシーを適用する様子を確認する
. **本番環境に昇格する** -- マージ、ビルド、Conforma ポリシーによる検証、リリースの承認を行い、デプロイする
. **名前空間のセキュリティ** -- Policy Controller が未承認のイメージの実行をどのように防ぐかを確認する
