= 脆弱性に早期に対処する
include::partial$_attributes.adoc[]
:imagesdir: ../../assets/images

従来のセキュリティ対策では、パイプラインの最後、あるいはそれより悪い場合はデプロイ後にスキャンを行います。その時点で脆弱性を修正すると、手戻りや遅延、緊急パッチが必要になります。より良い方法は、 **シフトレフト** です。開発者がコードを書いている間に、できるだけ早く脆弱性を特定して修正できるツールを提供します。

このセクションでは、セキュリティが強化された開発環境をセットアップし、Red Hat Dependency Analytics を使って、コミットをプッシュする前にアプリケーションの依存関係にある脆弱性を見つけて修正します。

NOTE: このモジュールでは、Red Hat Developer Hub のすべての機能や、日々の開発者のワークフローをどのように支援するかについては扱いません。開発者エクスペリエンスについては、xref:module-01/00-intro.adoc[モジュール 1: 開発者エクスペリエンス] を参照してください。ここでは、開発プロセスに追加されたセキュリティガードレールに焦点を当てます。

== セクション 2: Red Hat Dependency Analytics

Red Hat Dependency Analytics (RHDA) は、アプリケーションの依存関係をリアルタイムで分析する IDE 拡張機能です。既知の脆弱性を特定し、修正の推奨事項を提示します。また、Red Hat の Trusted Profile Analyzer (TPA) と連携して脆弱性データを拡充します。これには、公開データベースでは入手できない Lightwell のバックポート修正も含まれます。

=== 演習 2: フレームワークの脆弱性を修正する

. `pom.xml` に戻り、脆弱性のある依存関係に赤い波線が表示されていることを確認します。

. 強調表示された依存関係にカーソルを合わせ、電球アイコンが表示されたら **Quick Fix** をクリックします。
+
image::m02-rhda-quickfix-hover.png[脆弱性のある依存関係にカーソルを合わせて Quick Fix オプションを表示,link=self,window=blank,width=500]
+
image::m02-rhda-quickfix.png[脆弱性のある依存関係に対する Quick Fix の提案,link=self,window=blank,width=500]
+
IMPORTANT: フレームワークの依存関係（Quarkus など）では、単一の依存関係に Quick Fix を適用すると、フレームワークの他の部分とバージョンが一致しなくなる可能性があります。以下に示すように、フレームワーク全体のバージョンを更新してください。

. `pom.xml` で Quarkus プラットフォームのバージョン（`quarkus.platform.version` を検索）を見つけ、より新しいバージョンに更新します。3.20.5 は **直接的な脆弱性** を修正する最新バージョンでした。
+
[source,xml,role="copypaste"]
----
<quarkus.platform.version>3.20.5</quarkus.platform.version>
----

. VSCode はファイルを自動保存します。RHDA は自動的に再分析します。レポートを確認してください。フレームワークの直接的な脆弱性がなくなり、その他の脆弱性も減っているはずです。

. **直接的な脆弱性** が見つからないため、警告は表示されません。ステータスバーの盾ボタン、または右上の円グラフをクリックしてください。
+
image::m02-rhda-shield-button.png[RHDA レポートを開くステータスバーの盾ボタン,link=self,window=blank,width=700]

. `quarkus-rest` 依存関係の周囲にあった波線が消えていることも確認してください。



. 次に、フレームワークを最新バージョンに更新します。
+
[source,xml,role="copypaste"]
----
<quarkus.platform.version>3.40.1</quarkus.platform.version>
----

. 自動保存後、分析が完了するまで待ちます。脆弱性の数が数件程度まで減るはずです。
+
image::m02-rhda-report-after-fix.png[フレームワークを最新バージョンに更新した後の RHDA レポート,link=self,window=blank,width=700]

=== なぜ重要なのか?

開発者がコードを書いている間に、可能な限り早い段階で脆弱性情報を提供すれば、十分な情報に基づいて判断できます。開発者は次のことができます。

* パイプラインを実行する前に、フレームワークのバージョンを更新するか判断する
* Lightwell のバックポート（依存関係のバージョンを変更しない、そのまま適用できる修正）とアップストリームの修正（破壊的変更をもたらす可能性のあるバージョン更新）の違いを理解する
* 重大度と悪用可能性に基づいて、修正する脆弱性の優先順位を決める

これが **シフトレフトセキュリティ** の本質です。CI/CD の失敗から数時間後に問題を発見するのではなく、開発者が情報とツールを持ち、自ら対処できます。

=== どのように実現したのか?

演習を読みやすくするため、以下に詳細を記載しています。展開して実装方法を確認してください。

.**展開して実装の詳細を表示**
[%collapsible]
====
Red Hat Dependency Analytics は、 **{tpa_url}[Trusted Profile Analyzer (TPA)^]** というバックエンドサービスに問い合わせます。この環境では TPA がクラスター上にデプロイされ、複数のソースから脆弱性データを取り込んでいます。

* **CVE List v5** -- 業界標準の脆弱性データベース
* **GitHub Security Advisories (GHSA)** -- オープンソースコミュニティからの脆弱性レポート
* **Lightwell** -- Red Hat の商用脆弱性インテリジェンスサービス。公開データベースでは入手できないバックポート修正やドロップイン置換を提供します。

RHDA は VS Code（および IntelliJ）の拡張機能で、ワークスペースの設定を通じて、このクラスターの TPA インスタンスを使用するように構成されています。

[source,json]
----
"redHatDependencyAnalytics.backendUrl": "https://rhda.{subdomain}"
----

`pom.xml`（または `package.json`、`go.mod` など）を開くと、RHDA は依存関係ツリーをバックエンドに送信します。バックエンドは取り込まれた脆弱性データと照合し、Lightwell の修正を含む拡充された結果を返します。

Dependency Analytics レポートから Trusted Profile Analyzer を直接開くこともできます。

image::m02-rhda-tpa-link.png[RHDA レポートから TPA を開く Take me there ボタン,link=self,window=blank,width=700]
====

=== 確認

この時点で、次のことができるはずです。

* pom.xml を開き、RHDA が脆弱性のある依存関係を強調表示することを確認する
* 重大度の内訳と修正方法が示された RHDA レポートを開く
* フレームワークのバージョンを更新し、脆弱性が減少したことを確認する
