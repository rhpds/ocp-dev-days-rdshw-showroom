= 脆弱性に早期対応する
include::partial$_attributes.adoc[]
:imagesdir: ../../assets/images

従来のセキュリティ対策では、パイプラインの最後、あるいはもっと悪い場合にはデプロイ後にスキャンします。その時点では、脆弱性を修正するには手戻り、遅延、緊急パッチが必要になります。より良い方法は、**shift left** です。つまり、開発者がコードを書いている早い段階で脆弱性を特定し修正できるようにツールを提供することです。

このセクションでは、保護された開発環境をセットアップし、その後 Red Hat Dependency Analytics を使用して、コミットをプッシュする前にアプリケーションの依存関係にある脆弱性を見つけて修正します。

NOTE: このモジュールでは、Red Hat Developer Hub のすべての機能や、それが開発者の日常的なワークフローをどのように支援するかについては扱いません。開発者体験については、xref:module-01/00-intro.adoc[モジュール 1: 開発者体験] を参照してください。ここでは、開発プロセスに追加されるセキュリティのガードレールに重点を置きます。

== セクション 2: Red Hat Dependency Analytics

Red Hat Dependency Analytics (RHDA) は、アプリケーションの依存関係をリアルタイムで分析する IDE 拡張機能です。既知の脆弱性を特定し、修正の推奨を提示し、Red Hat の Trusted Profile Analyzer (TPA) と連携して、公開データベースにはない Lightwell のバックポート修正を含む、より充実した脆弱性データを提供します。

+
image::m02-rhdh-devspaces-link.png[サンドボックスコンポーネントページの Dev Spaces リンク,link=self,window=blank,width=700]

TIP: 作成者を信頼するかどうかのポップアップが表示されたら、**Yes, I trust the authors** をクリックします。

=== 演習 2: フレームワークの脆弱性を修正する

. `pom.xml` に戻り、脆弱な依存関係に赤い波線が付いていることを確認します。

. ハイライトされた依存関係にマウスオーバーし、電球が表示されたら **Quick Fix** をクリックします。
+
image::m02-rhda-quickfix-hover.png[脆弱な依存関係にマウスオーバーして Quick Fix オプションを表示している様子,link=self,window=blank,width=500]
+
image::m02-rhda-quickfix.png[脆弱な依存関係に対する Quick Fix の提案,link=self,window=blank,width=500]
+
IMPORTANT: Quarkus のようなフレームワーク依存関係では、単一の依存関係に quick fix を適用すると、フレームワークの他の部分とバージョンの不整合が発生する可能性があります。代わりに、下に示すようにフレームワーク全体のバージョンを更新します。

. `pom.xml` で Quarkus のプラットフォームバージョン（`quarkus.platform.version` を探します）を見つけ、より新しいバージョンに更新します。3.20.5 は、**直接脆弱性** を修正する最新バージョンでした:
+
[source,xml,role="copypaste"]
----
<quarkus.platform.version>3.20.5</quarkus.platform.version>
----

. VSCode がファイルを自動保存します。RHDA は自動的に再分析します。レポートを確認すると、フレームワークの直接脆弱性は消え、他の項目も減少しているはずです。

. **直接脆弱性** が見つからないため警告は表示されません。ステータスバーのシールドボタン、または右上の円グラフをクリックできます。
+
image::m02-rhda-shield-button.png[RHDA レポートを開くためのステータスバーのシールドボタン,link=self,window=blank,width=700]

. `quarkus-rest` 依存関係の周囲にあった波線が消えていることにも注目してください。



. 次に、最新のフレームワークバージョンに更新します:
+
[source,xml,role="copypaste"]
----
<quarkus.platform.version>3.40.1</quarkus.platform.version>
----

. 自動保存後、分析が完了するのを待ちます。脆弱性の数は数件まで減るはずです。
+
image::m02-rhda-report-after-fix.png[最新のフレームワークバージョンに更新した後の RHDA レポート,link=self,window=blank,width=700]

=== なぜこれが重要なのか？

開発者に対して、コードを書いている最中という最も早い段階で脆弱性情報を提供すると、より適切な判断ができるようになります。たとえば、以下が可能になります:

* パイプラインが一度も実行される前にフレームワークのバージョン更新を選択する
* Lightwell のバックポート（依存関係のバージョンを変更しない差し替え可能な修正）と、上流の修正（互換性のない変更を伴う可能性があるバージョンアップ）の違いを理解する
* 深刻度と悪用可能性に基づいて、どの脆弱性を優先して修正するか判断する

これこそが **shift-left security** の本質です。つまり、開発者が数時間後の CI/CD の失敗で問題を発見するのではなく、行動するための情報とツールを手にすることです。

=== どのように実施したのか？

演習を読みやすくするため、詳細を以下に記載しています。展開して実施方法を確認してください。

.**展開して実装の詳細を見る**
[%collapsible]
====
Red Hat Dependency Analytics は、**{tpa_url}[Trusted Profile Analyzer (TPA)^]** というバックエンドサービスを照会します。この環境では、TPA はクラスター上にデプロイされ、複数のソースから脆弱性データを取り込みます:

* **CVE List v5** -- 業界標準の脆弱性データベース
* **GitHub Security Advisories (GHSA)** -- オープンソースコミュニティからの脆弱性レポート
* **Lightwell** -- Red Hat の商用脆弱性インテリジェンスサービス。公開データベースにはないバックポート修正やドロップイン置換を提供します

RHDA は VS Code（および IntelliJ）の拡張機能で、ワークスペース設定を通じてこのクラスターの TPA インスタンスを使用するよう設定されています:

[source,json]
----
"redHatDependencyAnalytics.backendUrl": "https://rhda.{subdomain}"
----

`pom.xml`（または `package.json`、`go.mod` など）を開くと、RHDA は依存関係ツリーをバックエンドに送信し、取り込まれた脆弱性データと照合して、Lightwell の修正を含む拡張結果を返します。

Dependency Analytics レポートから Trusted Profile Analyzer を直接開くこともできます:

image::m02-rhda-tpa-link.png[RHDA レポートから TPA を開くための Take me there ボタン,link=self,window=blank,width=700]
====

=== 確認

ここまでで、以下ができるはずです:

* pom.xml を開き、RHDA が脆弱な依存関係をハイライトするのを確認する
* 深刻度別の内訳と修正内容を含む RHDA レポートを開く
* フレームワークのバージョンを更新し、脆弱性が減少するのを確認する

'''
