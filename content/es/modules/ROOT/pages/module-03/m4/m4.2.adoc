=== Iniciar el ciclo de desarrollo

Desde este momento, trabajarás en un ciclo de desarrollo rápido: _Camel JBang_ se ejecuta en modo de desarrollo, lo que significa que cada cambio que hagas en la ruta se detecta y aplica de inmediato. Puedes modificar el flujo, guardar el archivo y observar el nuevo comportamiento al instante, sin reiniciar.

Empieza ejecutando la ruta de Camel tal como está para ver el comportamiento del marcador de posición:

{blank}

[.copypaste]
****
camel run agent --dev
****

[TIP]
--
.¿Qué hace este comando?
[%collapsible]
====
* `camel run agent`: carga los recursos del directorio `agent` y ejecuta la ruta definida en él.
* `--dev`: modo de desarrollo; recarga automáticamente al guardar cambios en cualquier archivo de origen.
====
--

.¿Por qué respondió así el bot?
[caption=]

El archivo `system.message` contiene el mensaje del sistema que guía el comportamiento del agente de IA. Una de sus reglas indica explícitamente al modelo que rechace la solicitud si no dispone de la herramienta adecuada:

----
# CRITICAL CONSTRAINTS
* **NO TOOL, NO URL:** If there is no tool fit for the job (missing),
  you MUST return Pattern 2 with the text: "I'm sorry, I don't have 
  the capability to retrieve that PDF right now."
----

Cuando registres las herramientas, el agente las descubrirá y utilizará automáticamente.

=== Conectar los servidores MCP

El proyecto incluye servidores MCP que proporcionan las herramientas necesarias para el flujo agéntico de Camel, pero el agente aún no los conoce. Debes conectarlos al flujo agéntico.

El siguiente diagrama muestra cómo Agentic Integration (una vez que MCP está activo) enruta las llamadas a herramientas desde el modelo de IA. Dos servidores MCP proporcionan conjuntos de herramientas distintos: Node.js y Camel Quarkus. Cuando el modelo de IA necesita una herramienta, Agentic Integration enruta la solicitud al servidor MCP correspondiente, que ejecuta la herramienta en los sistemas de backend y devuelve el resultado.

[TIP]
--
En Camel no necesitas servidores MCP para definir herramientas. Puedes definirlas directamente como rutas normales que comienzan con el componente `langchain4j-tools`. La ruta describe lo que hace la herramienta: el agente la descubre automáticamente mediante etiquetas y la invoca cuando la necesita.

Por ejemplo, así definirías una herramienta local que recupera la URL del PDF de un documento de póliza determinado:

image::module-03/m4/kaoto-tool-route.png[width=50%]

La ruta comienza con el origen `langchain4j-tools`, procesa la solicitud mediante una serie de pasos y devuelve el resultado al LLM. No se necesita ninguna conexión especial. Camel usa etiquetas para asociar agentes con herramientas: cuando la etiqueta de un agente coincide con la de una herramienta, el agente puede invocarla.

=== Modificar el documento de póliza

El bot de IA puede hacer más que recuperar datos: también puede actuar sobre ellos. Imagina que el cliente ha cambiado de opinión y quiere eliminar una cobertura. Pide al asistente de IA que modifique el documento de póliza:

{blank}

[.copypaste.value]
****
El cliente desea eliminar la cobertura de asistencia en carretera. ¿Podrías actualizar el documento de póliza?
****

El sistema agéntico inspecciona el documento de póliza, identifica la cobertura correspondiente, activa las herramientas necesarias para actualizar la base de datos y responde con un resumen de los cambios:

{blank}

:fig-time: 6:49 PM
:fig-user-msg: El cliente desea eliminar la cobertura de asistencia en carretera. ¿Podrías actualizar el documento de póliza?
:fig-bot-msg: Se actualizaron los registros de la base de datos. Se eliminó la cobertura de asistencia en carretera (elemento 4) y se recalcularon los valores del resumen. ¿Quieres ver el nuevo documento de póliza?
include::_figures/rc-interaction.adoc[]

El sistema agéntico actuó de forma autónoma: inspeccionó el documento de póliza, identificó la cobertura, actualizó el registro en la base de datos, recalculó los totales y confirmó los cambios. Todo a partir de una sola solicitud en lenguaje natural.

Fíjate en la respuesta del bot: puede sugerir que consultes el documento de póliza actualizado (los LLM son impredecibles, por lo que la redacción exacta puede variar). Si lo hace, responde simplemente `sí`. Si no, pídele que muestre el documento de póliza modificado:

{blank}

[.copypaste.value]
****
¿Puedes mostrarme el documento de póliza actualizado?
****

En cualquier caso, el bot responde con el enlace al PDF actualizado:

=== Crear un ticket

Un proceso de atención al cliente rara vez termina con una sola acción. Modificar una póliza involucra a varios departamentos: confirmar los cambios, procesar cualquier reembolso, actualizar los registros de la póliza y avisar al cliente. En lugar de gestionar cada paso manualmente, pide al agente de IA que cree un ticket para coordinarlo todo:

{blank}

[.copypaste.value]
****
¿Podrías crear un ticket? Incluye los detalles explicados y pide a los departamentos correspondientes que procesen la modificación de la póliza.
****

El sistema agéntico reúne el contexto de la conversación, crea un ticket en el sistema de mesa de ayuda y responde con una confirmación:

{blank}

:fig-time: 6:52 PM
:fig-user-msg: ¿Podrías crear un ticket? Incluye los detalles explicados y pide a los departamentos correspondientes que reembolsen al cliente.
:fig-bot-msg: Se creó un ticket con el ID 1025. ¿Quieres compartirlo con el cliente?
include::_figures/rc-interaction.adoc[]

{empty} +

IMPORTANT: Antes de continuar, asegúrate de haberte incorporado a _Matrix_ y de haber aceptado la invitación a la sala; el ticket se compartirá con el cliente allí. Recuerda que _Matrix_ representa el lado del cliente, mientras que _Rocket.Chat_ es donde trabaja el agente de soporte. Si aún no lo has hecho, sigue las instrucciones de xref:module-03/m2/m2.1.adoc[incorporación a la plataforma Matrix,window=_blank].

La interacción anterior muestra una solicitud y una respuesta sencillas, pero, como los LLM no son deterministas, el bot podría haber respondido de otra manera. Esto es lo que puedes esperar y cómo gestionar cada caso:

* **El bot pregunta si debe compartir el ticket** (como se muestra arriba): responde:
+
{blank}
+
[.copypaste.value]
****
Sí, compártelo con el cliente, por favor.
****
+
{blank}

* **El bot no menciona que vaya a compartirlo**: pídeselo explícitamente:
+
{blank}
+
[.copypaste.value]
****
¿Podrías compartir el ticket con el cliente?
****
+
{blank}
+
* **El bot comparte el ticket automáticamente** sin preguntar: no hace falta hacer nada, continúa con el siguiente paso.
+
{empty} +

En cualquier caso, el resultado final es el mismo: el bot comparte el ticket y el cliente recibe un enlace al sistema de mesa de ayuda:

{blank}

:fig-time: 6:53 PM
:fig-user-msg: Sí, compártelo con el cliente, por favor.
:fig-bot-msg: El ticket #1025 se compartió correctamente con el cliente. Recibirá un enlace al sistema de mesa de ayuda.
include::_figures/rc-interaction.adoc[]

Recuerda: el cliente se comunica desde la plataforma de mensajería _Matrix_. El bot indicó que compartió el ticket, lo que significa que el cliente debería haber recibido un mensaje con la referencia del ticket. Cambia a la ventana de _Matrix_ y compruébalo.
