=== Probar sin una clave de API

La AuthPolicy que implementaste no se limita a bloquear o permitir solicitudes; también distingue entre niveles de servicio. Así es como la Herramienta de perfil del cliente enruta las solicitudes a través de la puerta de enlace:

Tanto el perfil Oro como el Plata los genera el mismo LLM. La AuthPolicy valida la clave de API incluida en cada solicitud para determinar qué nivel de servicio proporcionar.

Esto se refleja en el archivo `application.properties`: hay dos definiciones de agente que apuntan al mismo endpoint, cada una con su propia clave de API:

[#config-snippet]
[source,properties, subs="attributes"]
----
# Gold agent - model configuration
forage.profile-gold.agent.model.kind=openai
forage.profile-gold.agent.model.name=qwen3-14b
forage.profile-gold.agent.base.url=http://internal-ai-gateway-openshift-default.ai-gateway.svc.cluster.local/{username}/v1
forage.profile-gold.agent.api.key=EMPTY

# Silver agent - model configuration
forage.profile-silver.agent.model.kind=openai
forage.profile-silver.agent.model.name=qwen3-14b
forage.profile-silver.agent.base.url=http://internal-ai-gateway-openshift-default.ai-gateway.svc.cluster.local/{username}/v1
forage.profile-silver.agent.api.key=EMPTY
----

=== Probar con claves de API válidas

Ahora que confirmaste que se rechazan las solicitudes no autenticadas, configuremos ambas claves de API para que la Herramienta de perfil del cliente pueda acceder al LLM.

{empty} +

. Detén el agente presionando kbd:[CTRL+C] en la terminal
+
{empty} +

. Ejecuta el comando (⏩ Fast-Forward) para configurar automáticamente ambas claves de API:
+
{blank}
+
[.copypaste]

****

* `step N` — salta a un paso específico
* `steps` — muestra todos los pasos disponibles

****
¿Apareció un error 401 cuando las claves estaban vacías y un análisis de nivel Oro después de configurar claves válidas?

[.success]
La AuthPolicy funciona según lo previsto: se bloquean las solicitudes no autenticadas y las claves válidas generan un perfil del cliente.

[.fail]
Comprueba que ambas claves de API en `application.properties` estén completadas (no tengan el valor `EMPTY`) y que el agente Camel se haya reiniciado correctamente.
