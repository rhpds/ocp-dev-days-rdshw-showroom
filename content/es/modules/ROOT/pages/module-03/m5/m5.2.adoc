=== Política de autenticación proporcionada por Connectivity Link
Ahora que conoces los conceptos y la arquitectura prevista, es hora de proteger el endpoint del LLM. En este ejercicio crearás una **AuthPolicy** aplicada a la HTTPRoute (`ai-proxy-route`) que aplica un esquema de autenticación basado en claves. Así, solo los usuarios autorizados con una clave de API válida podrán acceder al LLM, y se extraerá información de identidad que podremos usar para limitar la velocidad en el siguiente paso.

NOTE: En este taller usaremos una autenticación sencilla mediante clave de API para que todo sea claro y simple, pero _Connectivity Link_ admite una amplia variedad de métodos de autenticación, incluidos JWT, OAuth2 y otros.

{empty} +

=== Comprende los secretos de usuario

Ya se han *creado previamente* dos secretos de claves de API. Es importante comprender su estructura, ya que ambas políticas hacen referencia a las etiquetas y anotaciones de estos secretos.

**Usuario de nivel Silver:**
[source,yaml,subs="attributes"]
----
apiVersion: v1
kind: Secret
metadata:
  name: trlp-tutorial-api-key-silver-{user-username}
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: my-llm-{user-username}
  annotations:
    kuadrant.io/groups: silver
    secret.kuadrant.io/user-id: {user-username}
stringData:
  api_key: [some_random_string]
type: Opaque
----

Campos clave de este secreto:

* `authorino.kuadrant.io/managed-by: authorino` -- Marca este secreto como gestionado por _Authorino_ (el motor de autenticación que utiliza _Connectivity Link_).
* `app: my-llm-{username}` -- Selector de etiquetas: AuthPolicy lo usa para detectar claves de API válidas.
* `kuadrant.io/groups: silver` -- Membresía de grupo (nivel Silver): determina qué nivel de limitación de velocidad se aplica.
* `secret.kuadrant.io/user-id: {user-username}` -- ID de usuario único: se utiliza como clave de contador para limitar la velocidad por usuario.

El secreto del nivel **Gold** tiene la misma estructura, pero con:

// == Protección del LLM con autenticación

// Ahora que conoces la arquitectura y la configuración, es hora de proteger el endpoint del LLM para que solo los usuarios autorizados de la organización puedan acceder. Crearás una **AuthPolicy** aplicada a la HTTPRoute `ai-proxy-route` que aplica:

// 1. **Autenticación mediante clave de API** -- Solo se permiten solicitudes con un token Bearer válido (que coincida con un secreto conocido).
// 2. **Autorización basada en grupos** -- Solo pueden acceder a la API los usuarios que pertenezcan a los grupos `lite` o `pro`.
// 3. **Extracción de identidad** -- Se extraen el grupo y el ID de usuario de las anotaciones del secreto, y se pasan a los servicios posteriores para que los use TokenRateLimitPolicy, que crearemos en la siguiente sección.

=== Revisa y aplica AuthPolicy

Examina AuthPolicy y *aplícalo* pegando el siguiente comando en tu terminal:

[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: ai-proxy-auth
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  rules:
    authentication:
      api-key-users:
        apiKey:
          selector:
            matchLabels:
              app: my-llm-{user-username}
        credentials:
          authorizationHeader:
            prefix: Bearer
    response:
      success:
        filters:
          identity:
            json:
              properties:
                groups:
                  selector: auth.identity.metadata.annotations.kuadrant\.io/groups
                userid:
                  selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/user-id
        headers:
          authorization:
            plain:
              selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/upstream-token
      unauthenticated:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Unauthenticated",
              "message": "Invalid or missing API Key."
            }
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied. Your account does not have the required permissions (gold/silver)."
            }
    authorization:
      allow-groups:
        opa:
          rego: |
            groups := split(object.get(input.auth.identity.metadata.annotations, "kuadrant.io/groups", ""), ",")
            allow { groups[pass:[_]] == "gold" }
            allow { groups[pass:[_]] == "silver" }
EOF
****

Campos clave de esta política:

* `namespace: {user-username}-devspaces` -- La política se crea en tu espacio de nombres.
* `name: ai-proxy-route` -- Se dirige a la HTTPRoute `ai-proxy-route`; todas las solicitudes que coincidan con esta ruta deben superar la autenticación.
* `app: my-llm-{user-username}` -- Busca secretos de _Kubernetes_ con esta etiqueta para encontrar claves de API válidas.
* `prefix: Bearer` -- Espera la clave de API en el encabezado `Authorization`.
* `kuadrant\.io/groups` -- Extrae la anotación de grupo del secreto coincidente y la expone como `groups` en el filtro de respuesta.
* `secret\.kuadrant\.io/user-id` -- Extrae la anotación del ID de usuario y la expone como `userid`.
* `rego` -- Regla de OPA (Open Policy Agent) que solo permite usuarios cuyo grupo sea `gold` o `silver`.
