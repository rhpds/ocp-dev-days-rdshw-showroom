[IMPORTANT]
====
En este laboratorio, usaremos la extensión **Migration Toolkit for Applications** para Visual Studio Code —la **extensión MTA**— en un entorno de Red Hat Dev Spaces que proporciona una interfaz gráfica basada en VS Code.

**Developer Lightspeed** no es una extensión independiente. Es la función de refactorización de código con IA de MTA. Lo que se instala en el IDE es la **extensión MTA**; incluye tanto el análisis estático de código de MTA como Developer Lightspeed (IA generativa).
====

Prepare el espacio de trabajo de OpenShift Dev Spaces ( `mta-lab` ) y la extensión MTA para el resto del laboratorio:

* Cree un perfil de migración (tecnologías de origen y destino)
* Confirme que Developer Lightspeed puede acceder al LLM del laboratorio mediante GenAI / `provider-settings.yaml`

Comenzaremos abriendo el entorno de desarrollo aprovisionado previamente y configurando la extensión MTA, incluidos los ajustes de Developer Lightspeed (IA), para modernizar la aplicación `parasol-insurance-eap` de Parasol Insurance.

Esto debería abrir la configuración de los ajustes del proveedor. MTA usa **provider-settings.yaml** para conectarse al LLM.

El espacio de trabajo del laboratorio viene preconfigurado con los ajustes del proveedor y las credenciales de LiteLLM. Confirme que el modelo **OpenShift** esté activo y que los campos de URL base y clave de API estén rellenados (ya deberían corresponder a su entorno de laboratorio).

TIP: Los ajustes del proveedor normalmente ya están rellenados para este laboratorio. Use el YAML siguiente solo si el archivo está vacío o incompleto (por ejemplo, después de restablecer un espacio de trabajo); este es un paso de recuperación, no un error previsto.

[.console-input]
[source,yaml,subs="+attributes,macros+"]
----
models:
  OpenShift: &active
    environment:
      OPENAI_API_KEY: "{litellm_virtual_key}"
    provider: ChatOpenAI
    args:
      model: "qwen3-235b"
      configuration:
        baseURL: "{litellm_api_base_url}"
active: *active
----

Confirme que los ajustes tengan los siguientes valores en los campos correspondientes.

- `OPENAI_API_KEY` : es la clave del LLM para el modelo alojado en OpenShift AI
- `model` : el nombre del modelo que estamos usando
- `baseURL` : la URL o ruta en la que el modelo escucha las solicitudes a través de la API de finalización de chat.
- `active` : por último, queremos asegurarnos de que este perfil esté activo. MTA se puede configurar con varios LLM, pero solo uno puede estar activo a la vez.

== Verificar

Confirme que el entorno de Dev Spaces y la extensión MTA (incluido Developer Lightspeed) estén configurados correctamente.

. Confirme que la extensión MTA esté configurada correctamente
* Con el icono de la extensión MTA seleccionado y la pestaña MTA Analysis View activa:
* Haga clic en el icono de engranaje situado en el lado derecho de la pantalla
* Se abrirá el panel **Get Ready to Analyze** en el lado derecho de la pantalla
* Los cuatro cuadros de mensajes deben tener marcas de verificación verdes y aparecer como completados

. Confirme que el espacio de trabajo de Dev Spaces apunte al repositorio correcto
* Haga clic en el icono de archivo situado en el lado izquierdo del entorno de Dev Spaces
* El _EXPLORER_ de archivos muestra el directorio **parasol-insurance-eap** (su copia de GitLab, no una muestra compartida)
* Si es necesario, expanda los directorios con las flechas del explorador de archivos; debería ver paquetes como `com.parasol.mdb` ( `EmailIntakeMDB` ) y `com.parasol.ejb` ( `ClaimService` )
