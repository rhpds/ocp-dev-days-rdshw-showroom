Entrambi i profili Gold e Silver sono generati dallo stesso LLM. AuthPolicy convalida l'API key presentata in ogni richiesta per determinare quale livello di servizio fornire.

Questo è rispecchiato nel file `application.properties` -- due definizioni dell'agent puntano allo stesso endpoint, ciascuna con la propria API key:

[#config-snippet]
[source,properties, subs="attributes"]
----
# Gold agent - model configuration
forage.profile-gold.agent.model.kind=openai
forage.profile-gold.agent.model.name=qwen3-14b
forage.profile-gold.agent.base.url=http://internal-ai-gateway-openshift-default.ai-gateway.svc.cluster.local/{username}/v1
forage.profile-gold.agent.api.key=EMPTY

# Silver agent - model configuration
forage.profile-silver.agent.model.kind=openai
forage.profile-silver.agent.model.name=qwen3-14b
forage.profile-silver.agent.base.url=http://internal-ai-gateway-openshift-default.ai-gateway.svc.cluster.local/{username}/v1
forage.profile-silver.agent.api.key=EMPTY
----

=== Verificare con API key valide

Ora che hai verificato che le richieste non autenticate vengono rifiutate, configuriamo entrambe le API key affinché lo Strumento profilo cliente possa raggiungere l'LLM.

{empty} +

. Arresta l'agent premendo kbd:[CTRL+C] nel terminale
+
{empty} +

. Esegui il comando (⏩ Fast-Forward) per configurare automaticamente entrambe le API key:
+
{blank}
+
[.copypaste]
****
ff
****
+
In questo modo vengono inseriti valori validi per le API key Gold e Silver nel file `application.properties`, utilizzando i secret del cluster.
+
[TIP]
--
.Comandi di navigazione del lab
[%collapsible]
====
Il workshop offre una serie di comandi di supporto per navigare nel lab:

* `ff` — passa rapidamente allo step successivo (configura automaticamente ciò che serve)
* `rw` — torna allo step precedente
* `step N` — passa a uno step specifico
* `steps` — elenca tutti gli step disponibili
* `start` o `restart` — ripristina lo stato iniziale
====
