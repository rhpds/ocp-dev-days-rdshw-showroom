== Autenticazione


=== Componenti predisposti per questa fase

Le seguenti risorse sono state configurate per consentirti di concentrarti sulla configurazione delle policy:

[cols="1,2", options="header"]
|===
| Risorsa | Scopo

| **GatewayClass, Gateway, HTTPRoute**
| Lo stack _Gateway API_ che instrada il traffico dall'interfaccia di chat all'API LLM. L'API LLM può essere un endpoint interno o esterno: il gateway nasconde questa differenza e offre un punto uniforme in cui applicare le policy.

| **Kuadrant Operator & System**
| L'operatore _Connectivity Link_, installato nel namespace `kuadrant-system`.

| **Segreti utente**
| Segreti con chiavi API per due livelli: `silver` e `gold`. I dettagli sono riportati di seguito.
|===

=== Policy di autenticazione basata su Connectivity Link
Ora che conosci i concetti e l'architettura prevista, è il momento di proteggere l'endpoint LLM. In questo esercizio creerai una **AuthPolicy** applicata alla HTTPRoute (`ai-proxy-route`) e che impone uno schema di autenticazione basato su chiave. In questo modo solo gli utenti autorizzati con una chiave API valida potranno accedere all'LLM; inoltre, verranno estratte informazioni sull'identità che useremo per il rate limiting nel passaggio successivo.

NOTE: Per questo workshop usiamo una semplice autenticazione con chiave API per mantenere le cose chiare e immediate, ma _Connectivity Link_ supporta un'ampia gamma di metodi di autenticazione, tra cui JWT, OAuth2 e altri.

{empty} +

=== Comprendere i segreti utente

Sono già stati *creati in anticipo* due segreti con chiavi API. È importante comprenderne la struttura, perché entrambe le policy fanno riferimento alle label e alle annotazioni di questi segreti.

**Utente del livello Silver:**
[source,yaml,subs="attributes"]
----
apiVersion: v1
kind: Secret
metadata:
  name: trlp-tutorial-api-key-silver-{user-username}
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: my-llm-{user-username}
  annotations:
    kuadrant.io/groups: silver
    secret.kuadrant.io/user-id: {user-username}
stringData:
  api_key: [some_random_string]
type: Opaque
----

Campi chiave di questo segreto:

* `authorino.kuadrant.io/managed-by: authorino` -- Indica che questo segreto è gestito da _Authorino_ (il motore di autenticazione alla base di _Connectivity Link_).
* `app: my-llm-{username}` -- Selettore di label: AuthPolicy lo usa per individuare le chiavi API valide.
* `kuadrant.io/groups: silver` -- Appartenenza al gruppo (livello Silver): determina quale livello di rate limit viene applicato.
* `secret.kuadrant.io/user-id: {user-username}` -- ID utente univoco, usato come chiave contatore per il rate limiting per utente.

{empty} +

Il segreto del livello **Gold** segue la stessa struttura, ma contiene:

* `kuadrant.io/groups: gold`

{empty} +

// == Proteggere l'LLM con l'autenticazione

// Ora che conosci l'architettura e la configurazione, è il momento di proteggere l'endpoint LLM, in modo che solo gli utenti autorizzati dell'organizzazione possano accedervi. Creerai una **AuthPolicy** applicata alla HTTPRoute `ai-proxy-route` che impone:

// 1. **Autenticazione con chiave API** -- Sono consentite solo le richieste con un Bearer token valido (corrispondente a un segreto noto).
// 2. **Autorizzazione basata sui gruppi** -- Possono accedere all'API solo gli utenti appartenenti ai gruppi `lite` o `pro`.
// 3. **Estrazione dell'identità** -- Il gruppo e l'ID utente vengono estratti dalle annotazioni del segreto e passati ai servizi a valle per essere usati dalla TokenRateLimitPolicy che creeremo nella sezione successiva.

=== Esamina e applica la AuthPolicy

Esamina la AuthPolicy e *applicala* incollando il seguente comando nel terminale:

[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: ai-proxy-auth
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  rules:
    authentication:
      api-key-users:
        apiKey:
          selector:
            matchLabels:
              app: my-llm-{user-username}
        credentials:
          authorizationHeader:
            prefix: Bearer
    response:
      success:
        filters:
          identity:
            json:
              properties:
                groups:
                  selector: auth.identity.metadata.annotations.kuadrant\.io/groups
                userid:
                  selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/user-id
        headers:
          authorization:
            plain:
              selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/upstream-token
      unauthenticated:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Unauthenticated",
              "message": "Invalid or missing API Key."
            }
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied. Your account does not have the required permissions (gold/silver)."
            }
    authorization:
      allow-groups:
        opa:
          rego: |
            groups := split(object.get(input.auth.identity.metadata.annotations, "kuadrant.io/groups", ""), ",")
            allow { groups[pass:[_]] == "gold" }
            allow { groups[pass:[_]] == "silver" }
EOF
****

Campi chiave di questa policy:

* `namespace: {user-username}-devspaces` -- La policy viene creata nel tuo namespace.
* `name: ai-proxy-route` -- Imposta come target la HTTPRoute `ai-proxy-route`: ogni richiesta che corrisponde a questa route deve superare l'autenticazione.
* `app: my-llm-{user-username}` -- Cerca i Secret di _Kubernetes_ con questa label per trovare le chiavi API valide.
* `prefix: Bearer` -- Si aspetta la chiave API nell'header `Authorization`.
* `kuadrant\.io/groups` -- Estrae l'annotazione del gruppo dal segreto corrispondente e la espone come `groups` nel filtro della risposta.
* `secret\.kuadrant\.io/user-id` -- Estrae l'annotazione dell'ID utente e la espone come `userid`.
* `rego` -- Regola OPA (Open Policy Agent) che consente solo agli utenti dei gruppi `gold` o `silver`.
