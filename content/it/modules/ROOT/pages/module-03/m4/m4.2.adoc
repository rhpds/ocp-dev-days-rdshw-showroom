=== Avviare il ciclo di sviluppo

Da questo momento lavorerai con un ciclo di sviluppo rapido: _Camel JBang_ è in esecuzione in modalità dev, quindi ogni modifica alla route viene rilevata e applicata immediatamente. Puoi modificare il flusso, salvare il file e osservare subito il nuovo comportamento senza riavviare.

Per prima cosa, esegui la route Camel così com’è per vedere il comportamento segnaposto:

{blank}

[.copypaste]
****
camel run agent --dev
****

[TIP]
--
.Cosa fa questo comando?
[%collapsible]
====
* `camel run agent` — carica le risorse nella directory `agent` ed esegue la route definita al suo interno.
* `--dev` — modalità dev; ricarica automaticamente le modifiche quando salvi un file sorgente.
====
--

.Perché il bot ha risposto così?
[caption=]
====
L’agente AI non ha accesso agli strumenti necessari: i server MCP non sono ancora stati collegati.

Il file `system.message` contiene il system prompt che guida il comportamento dell’agente AI. Una delle sue regole indica esplicitamente al modello di rifiutare quando non dispone dello strumento adatto:

----
# CRITICAL CONSTRAINTS
* **NO TOOL, NO URL:** If there is no tool fit for the job (missing),
  you MUST return Pattern 2 with the text: "I'm sorry, I don't have 
  the capability to retrieve that PDF right now."
----

Una volta registrati gli strumenti, l’agente li individuerà e li userà automaticamente.
====

=== Collegare i server MCP

Il progetto include server MCP che forniscono gli strumenti necessari al flusso agentico Camel, ma l’agente non li conosce ancora. Devi collegarli al flusso agentico.

Il diagramma seguente mostra come Agentic Integration, una volta attivo MCP, instrada le chiamate agli strumenti provenienti dal modello AI. Due server MCP forniscono set di strumenti distinti: Node.js e Camel Quarkus. Quando il modello AI ha bisogno di uno strumento, Agentic Integration inoltra la richiesta al server MCP appropriato, che esegue lo strumento sui sistemi backend e restituisce il risultato.

=== Creare un ticket

Un processo di assistenza clienti raramente si conclude con una sola azione. Modificare una polizza coinvolge più reparti: confermare le modifiche, elaborare eventuali rimborsi, aggiornare i record della polizza e avvisare il cliente. Invece di gestire manualmente ogni passaggio, chiedi all’agente AI di creare un ticket che coordini tutto:

{blank}

[.copypaste.value]
****
Puoi creare un ticket? Includi i dettagli descritti e chiedi ai reparti competenti di elaborare di conseguenza la modifica della polizza.
****

Il sistema agentico raccoglie il contesto dalla conversazione, crea un ticket nel sistema HelpDesk e risponde con una conferma:

{blank}

:fig-time: 6:52 PM
:fig-user-msg: Puoi creare un ticket? Includi i dettagli descritti e chiedi ai reparti competenti di rimborsare il cliente di conseguenza.
:fig-bot-msg: È stato creato un ticket con ID 1025. Vuoi condividerlo con il cliente?
include::_figures/rc-interaction.adoc[]

{empty} +

IMPORTANT: Prima di proseguire, assicurati di aver completato l’onboarding su _Matrix_ e di aver accettato l’invito alla stanza: il ticket verrà condiviso lì con il cliente. Ricorda che _Matrix_ rappresenta il lato del cliente, mentre _Rocket.Chat_ è l’ambiente di lavoro dell’agente di supporto. Se non l’hai ancora fatto, segui le istruzioni di xref:module-03/m2/m2.1.adoc[onboarding della piattaforma Matrix,window=_blank].

L’interazione qui sopra mostra una semplice richiesta e risposta, ma poiché gli LLM non sono deterministici, il bot potrebbe aver risposto diversamente. Ecco cosa aspettarti e come gestire ogni caso:

* **Il bot chiede di condividere il ticket** (come mostrato sopra): rispondi con:
+
{blank}
+
[.copypaste.value]
****
Sì, condividilo con il cliente.
****
+
{blank}

* **Il bot non menziona affatto la condivisione**: chiediglielo esplicitamente:
+
{blank}
+
[.copypaste.value]
****
Puoi condividere il ticket con il cliente?
****
+
{blank}
+
* **Il bot condivide automaticamente il ticket** senza chiedere: non serve fare nulla, continua con il passaggio successivo.
+
{empty} +
